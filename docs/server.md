# Local server (WP-41)

`codeskimr serve` starts the local server: REST generated from the command registry, a WebSocket with the domain events, and the protection that blueprint S-04 asks for. The decisions are in ADR 0024. WP-42 added the browser UI delivery, the launch code and the CSP (ADR 0028, ADR 0030). The OpenAPI document is not part of these packages.

## Structure

- `codeskimr_server` is a driving adapter. `CommandApi` holds the commands that are exposed over REST, `Server` builds the router, `BoundServer` serves it. It depends on `application`, `domain` and `codes` only.
- The composition root (`crates/app`, `serve.rs`) wires it: it creates the `Registry` and `CommandApi`, resolves the `Principal` once (`principal.rs`), loads or creates the installation token (`installation_token.rs`) and binds `127.0.0.1:{server.port}`.
- `commands.rs` turns a typed `Command` into a route (`expose::<C>()`, needs `DeserializeOwned` input and `Serialize` output). The call goes through `Registry::execute`, so the permission is checked there as for every other surface. Commands run on the blocking pool, never on the async runtime.

## Routes

| Route | Meaning |
|---|---|
| `GET /api/v1/commands` | the commands the caller may run: `id`, `title_key`, `description_key`, `shortcut`, `read_only` |
| `POST /api/v1/commands/{id}` | runs a command; body = JSON input (none = `null`), answer = JSON output |
| `GET /api/v1/events` | WebSocket, one JSON text message per event |
| `GET /api/v1/ui-config` | public, no secret: editor template, allowed schemes, default theme |
| `POST /api/v1/session/launch-code` | Bearer token; returns a new one-time launch code |
| `GET /api/v1/session/launch-code` | Bearer token; `pending` is true while a code waits to be used |
| `POST /api/v1/session/exchange` | body `{ "code": … }`; returns the token once (`API-403` if wrong, used or expired) |
| `POST /api/v1/level2/confirm-window` | body `{ "project_id": n }`; opens the console window of the level 2 confirmation, see below |
| `/mcp` | MCP over streamable HTTP (WP-48); every request needs the Bearer token, see below |
| everything else | files of the UI folder; paths without extension give `index.html` |

Every error answer is `{ "code": "API-401", "description": "…" }` with the HTTP status of the code's class. Unknown paths give `API-201`, a wrong method `API-101` (405).

## Checks, in this order

1. `Host` is the bound address or `localhost` with the same port; `Origin`, if present, is `http://` plus one of these. Otherwise `API-402` (403). This is the protection against DNS rebinding and cross-site requests.
2. A command with `read_only = false`, a command with the permission `read_source` (it returns source text, ADR 0035) and an id that does not exist need `Authorization: Bearer <installation token>` (`API-401`).
3. The principal holds the permission of the command and the command exists. Both failures give the same answer, `API-201` (404), so the answer tells nothing about which commands exist (ADR 0044). This comes before the body is read.
4. The body is at most 1 MiB (`API-501`, 413) and, if there is one, `application/json` (`API-101`).

CORS is closed: no `Access-Control-*` header is ever sent and there is no `OPTIONS` route. Every answer has `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin` and a strict `Content-Security-Policy` (no inline script or style, no framing, connections only to the own host).

## The level 2 switch (ADR 0071)

The Projects screen shows whether the second pass is on for a project and can start the confirmation. Two commands carry the state; one route opens the window. Neither can confirm anything: the consent is written only by `level2 confirm`, typed by the owner in a console.

- `level2.status` (read, no token) takes `{ "project": id }` and returns `{ "state": "on" | "off" | "not_enabled" | "locked", "confirmed": bool, "launch": "window" | "copy" }`. `not_enabled` is the switch in the user configuration, `off` a switch that is on but not confirmed, `locked` a team server, which runs no indexers (ADR 0033, decision 10; the single-user program never answers it today, the branch is tested with a fake). `launch` says whether this system opens a window (`window`) or the page shows a command to copy (`copy`). The answer holds no path.
- `level2.revoke` (right `revoke_indexer`, token) takes the same input and returns the same answer after the consent was withdrawn.
- `POST /api/v1/level2/confirm-window` lies outside the registry and has its own order: `Host` and `Origin` (`API-402`), `Sec-Fetch-Site` (`API-402`, a browser value other than `same-origin` or `none`), `application/json` (`API-101`), token (`API-401`), loopback peer (`SEC-403`), right `open_confirmation` (`AUTH-401`, 403), body (`API-101`), project (`PRJ-201`; `SEC-403` for a name that hides text), switch (`CFG-105`, 409), pause (`API-504`, 429 with `Retry-After`), start. The answer is `{ "launch": "window" }` or, on a system without a window, `{ "launch": "copy", "command": "codeskimr level2 confirm <id>" }`. A failed start is `APP-604` (500); the pause stays so a broken start cannot be repeated quickly. The loopback check is tested from end to end with `BoundServer::serve_as_peer`, which fixes the peer address of every request; it is for tests only, and a source scan (`crates/server/tests/peer_seam.rs`) fails if any other source file of the repository (crates, tools, build scripts) uses it (issue #531).
- The pause (`level2.confirm_window_cooldown_seconds`, default 30) is shared by all projects of the installation. The page polls `level2.status` every `ui.level2_poll_seconds` (default 2) for at most `ui.level2_poll_max_seconds` (default 300); both values come from `GET /api/v1/ui-config`, as does `ui.approximate_languages` (the languages whose usages the screens mark as an approximation: Python, C# and Kotlin by default).
- The window gets the global options the server was started with (`--data-dir`, `--config`, `--set`) as separate arguments, and they show in the command line of the terminal; keep a secret in the configuration file, not in `--set`. On macOS the arguments are quoted for POSIX shells; with `tcsh` or `csh` as login shell a `!` in a value can still be expanded, which matters only for values the owner gave at the start of the server.
- On a system without a window (`copy`) nothing is started, so no pause is set and `API-504` never occurs there (ADR 0071, decision 4a speaks of an opened window).
- The server starts no process. The port `ConfirmationWindow` is implemented in `crates/app/src/confirmation_window.rs` (Windows: a new console, macOS: `osascript` with a constant script, Linux: none, the page shows the command). `crates/server/tests/no_process.rs` fails if the server source names a way to start a program. The MCP service has no tool for the switch.

## MCP at `/mcp` (WP-48)

The running app offers the MCP server of `docs/mcp.md` on the same listener, as blueprint 10.4 asks: `codeskimr serve` builds the tools once (`crates/app/src/mcp.rs`, `http_service`) and hands the `tower` service of `codeskimr_mcp::http_service` to `Server::with_mcp`. The server crate does not know `rmcp`; it only mounts a service at `/mcp`.

- **Checks:** the `Host` and `Origin` checks of step 1 come first, as for every route. Then the token: every request to `/mcp`, whatever its method, needs `Authorization: Bearer <installation token>` (`API-401`, 401), also a pure read. Tool answers carry the structure of the code, and without the token any program on this machine could read it through the open loopback port; the token proves that the caller can read the keystore, like in ADR 0035. A client such as Claude Code or Cursor is configured with the URL `http://127.0.0.1:7421/mcp` and the header `Authorization: Bearer <token>`. How the token reaches such a client is the task of the installation (the token is never shown by a command, see below).
- **Who calls:** every request runs as the principal of the composition root, the local owner in single-user mode. After 1.0 the team edition resolves a principal per personal access token and builds one handler per caller (ADR 0019); the tools check their permission as before (`rescan` needs `scan`).
- **Error format:** a method the MCP service does not offer (`GET`) answers `API-101` with status 405 and a body it cannot read (not JSON) answers `API-101` with status 400, both as `{ "code", "description" }` like every other route; JSON-RPC errors stay in the JSON-RPC answer.
- **Stateless:** every request is answered on its own with a JSON body, no session survives a request, and there is no `GET` stream. A restart of the app loses nothing; a client that sends `Mcp-Session-Id` is not tracked. The body is at most 1 MiB.
- **Shared instance:** the service uses the database file of the app and the event bus of the server. A `rescan` of an agent publishes the same events as a scan from the UI, so the UI shows its progress. The store is opened a second time next to that of the commands (one connection each, same file); sharing the connection waits until the commands take a store from the composition root.
- **Projects:** the app has no default project. A call that names none is `MCP-101` with `params.detail = project`; the ids come from `projects.list` over REST. An MCP tool that lists the projects is not part of WP-48.
- **Not yet:** the resources (`codeskimr://…`) belong to the MCP server itself, not to this transport.

## The installation token

`csk_` and 64 hex digits (256 random bits), created at the first `serve` and kept in the credential store (OS keystore). The server keeps the BLAKE3 digest for checking requests. The token text is read in `installation_token::digest_of` and, while a launch code is waiting, held as a secret string (see below); it is never logged and not part of any `Debug` output. The prefix is masked by the log redaction (S-01). There is no command that shows the token. The browser UI gets it through a launch code:

1. `codeskimr open` reads the token from the keystore and asks the server for a code (128 random bits, valid `ui.launch_code_seconds`, default 60, usable once, one code at a time).
2. It writes a redirect page to a launch file (mode 0600, created exclusively, in a private folder with mode 0700; on Windows the folder gets access rules for the user alone) and starts the browser with that `file://` path. The folder and everything above it must belong to the user or the administrator and must not be writable by everybody (unless sticky); otherwise the file is not created (`APP-202`). On Windows the folder, the file and every folder above up to the drive root must belong to the user, the administrators, the system account or the Windows installer service (the usual owner of a drive root); a folder above that belongs to another account ends with `APP-202`, and the log names that folder (event `launch_parent_refused`). The folders above are checked before the access rules of the launch folder are set and again after the file was made. This is strict on purpose: a data folder on a network share (folders there often belong to a domain account or an account of the file server), in a redirected company profile, or on a second drive below a folder that another account or an earlier Windows installation made is refused; the remedy is a data folder (`--data-dir`) whose folders all belong to the own account. Whether the access rules of a folder above let others write to it is not checked on Windows. The code is never on a command line. `--no-browser` only prints the path. `--no-browser --print-url` (ADR 0088) skips the file and prints the address `http://127.0.0.1:<port>/#code=…` instead, returns at once and starts no browser; it exists for remote browser tests that cannot open `file://`.
3. The page redirects to `http://127.0.0.1:PORT/#code=…`. The fragment is not sent to the server. The UI removes it with `history.replaceState`, then posts the code to the exchange route and keeps the token in `sessionStorage` only.
4. `open` polls until the code is taken or has expired and then deletes the file.

Threat note: `codeskimr open` sends the token to the port of `server.port` over plain HTTP on the loopback address. If no server runs there, another local user could listen on that port and read it. This is an accepted risk of the single-user mode (ADR 0030). The server holds the token text for at most the life of the code. Another OS user cannot read the launch file (0600 in a 0700 folder). A process of the same user could read it, but that user can read the keystore anyway. Within the 60 seconds a local process that guesses the code would need 2^128 tries, and a wrong code does not burn the valid one. A used or expired code is gone for good. With `--print-url` the code is in the output of the command: whoever reads that output within the lifetime can sign in once, so the switch must be named on purpose and the output kept private.

## Limits of the commands that scan

At most 4 scans run at the same time over all projects; one more gets `PRJ-501`. `projects.add` refuses Git addresses and branch names that `git` or `ssh` could read as options or commands (a leading `-`, blanks, control characters, a transport helper such as `ext::`, more than 2048 characters for the address and 255 for the branch, and the characters of `git check-ref-format` in a branch) with `PRJ-101`. The `.codeskimr.toml` of a scanned folder can lower `scan.max_source_mb` and `scan.parse_timeout_ms` but not raise them (#54, ADR 0040). A folder is accepted if it is an absolute path that exists; in single-user mode the owner may scan any folder, a root allow-list belongs to the team server (S-05, ADR 0019). The scan does not follow links that leave the project folder (tested in the canary suite). `projects.list` needs no token and shows absolute paths: that is the decision of S-04 for single-user mode, because it only reads and the port is loopback only.

## Events

Messages have a `type` and ids and counts only: `scan_progressed` (`project`, `stage`, `done`, `total`, `elapsed_ms` = milliseconds since the stage started; a stage reports once more when it is over, with its last counts and its whole time; while the stage `persist` writes the snapshot, a report also carries `step` = the label of the step of the write, `step_number` = its place from one and `steps` = how many steps a write has at most, and each new step is reported when it begins), `snapshot_created` (`project`, `snapshot`, `pack_load_ms` = milliseconds that loading language packs took during the scan, which a screen leaves out of the duration, ADR 0059; `unchanged` = the scan found no file changed and confirmed the snapshot the project had, ADR 0093), `files_changed` (`project`, `files`, `rescan`), `scan_stopped` (`project`, `reason` = `cancelled` or `failed`, `code`), `alerts_changed` (`project`, `open` = number of open alerts; see below), `level2_progressed` (`project`, `language`, `stage` = `level2_running` or `level2_importing`) and `level2_finished` (`project`, `snapshot`, `checked`, `skipped`, `failed` = numbers of languages; ADR 0072). Both level 2 events carry ids, labels and counts only, never a path or a tool. The stream needs the `read` permission; messages from the client are ignored (limit 1 KiB). A thread per connection carries the events from the bus (which is synchronous) to a bounded queue (256 events) of the runtime and ends when the socket is gone. A client that does not keep up and fills the queue, or does not take a message within 10 seconds, is disconnected (close code 1013, "try again later") and connects again. An idle stream is pinged every 20 seconds and ends if it hears nothing for 90 seconds. At most 16 streams run at once; one more gets `API-502` (503).

## Annotations and alerts (ADR 0068)

The commands below run over `POST /api/v1/commands/{id}` like every other command. Reading needs `read` and no token; changing needs `annotate` and the installation token (`API-401` without it). A caller without the right gets `API-201` on the route (`AUTH-401` from `CommandApi::run`), and a denied call changes nothing and publishes no event. The local owner and the remote client of `serve` hold `annotate`; a reader does not.

A symbol is named by `target`: `{ "kind": "method", "name": "App.Order.Total", "parameters": ["int"] }` (kind label, qualified name, parameter types). `parameters` may be left out; a filter without it matches every overload, and a new annotation on an overloaded name should give them. An annotation whose symbol is gone from the newest scan has `without_target: true` and can be given a new symbol with `annotations.update` (`target`).

| Command | Permission | Input | Answer |
|---|---|---|---|
| `annotations.list` | read | `project`, `symbol?` (a `target`), `kind?` (`critical`, `note`, `task`), `status?` (`open`, `in_progress`, `done`), `without_target?`, `offset?`, `limit?` | page of annotations |
| `annotations.summary` | read | `project`, `offset?`, `limit?` | page with one row per annotated symbol: `target`, `critical`, `notes`, `tasks_done`, `tasks_total`, `without_target`, ordered by qualified name |
| `annotations.create` | annotate | `project`, `target`, `kind?`, `title?`, `text?`, `status?`, `due?`, `assignee?` | the annotation |
| `annotations.mark_critical` (K), `annotations.add_note` (N), `annotations.add_task` (T) | annotate | as `create`, the kind is fixed (a different `kind` is `API-101`) | the annotation |
| `annotations.update` | annotate | `project`, `id`, `target?` (assigns it to another symbol), `title?`, `status?`, `text?`, `due?`, `assignee?` | the annotation |
| `annotations.delete` | annotate | `project`, `id` | `{ "id": … }` |
| `alerts.list` | read | `project`, `state?` (`open` by default, `dismissed`), `kinds?` (`changed`, `removed`, `orphaned`), `offset?`, `limit?` | `{ items, total, offset, limit, next_offset, open }` |
| `alerts.dismiss` | annotate | `project`, `alert` | `{ "dismissed": 1, "open": n }` |
| `alerts.dismiss_all` | annotate | `project`, `kinds?`, `confirm` | `{ "dismissed": n, "open": m }`; without `"confirm": true` the call is `API-101` and dismisses nothing |

- **Pages** are `{ items, total, offset, limit, next_offset }`; `next_offset` is `null` on the last page. `limit` defaults to `annotations.default_page_size` (100) and is held to `1..=annotations.max_page_size` (500).
- **`text` and `title`** are limited by `annotations.max_text_chars` and `annotations.max_title_chars`; a text that is too long is refused, one that is blank counts as absent. A task without `status` is `open`.
- **Limits of the symbol and the assignee:** `annotations.max_assignee_chars` (`ANN-104`), `annotations.max_name_chars`, `annotations.max_parameter_chars` and `annotations.max_parameters` (`ANN-105`) hold the assignee and the symbol an annotation is put on; they apply to `create` and to `update`.
- **`update`** reads a field that is missing as "keep it". `text`, `due` and `assignee` can also be `null`, which removes them; `kind` cannot be changed.
- **An annotation** has `id`, `project`, `target`, `kind`, `title`, `text` (the reason of a critical mark), `status`, `due` (seconds since the Unix epoch), `assignee`, `author`, `created`, `updated`, `without_target`. **An alert** has `id`, `annotation`, `target`, `reason` (the text of the critical mark), `kind`, `state`, `counter`, `first_seen`, `last_seen`, `dismissed`, `snapshot`, `commit`, `trigger` (`scan`, `watcher`, `fetch`), `changes` (`content`, `signature`, `cc`, `loc`), `references` (provisional, matched by name) and `closest`.
- **Dismissing** takes the code as it is now as the new baseline, so the same state raises no second alert. Deleting a critical annotation closes its open alert. Errors: `ANN-201` for an unknown annotation, `ANN-202` for an unknown alert or one that is already dismissed, `ANN-301` for a second critical mark on a symbol, and the store's code for a symbol that is not in the newest scan.
- **Event:** `alerts_changed` (`project`, `open`) goes to the WebSocket after a dismissal, a bulk dismissal, a deletion that closes an alert and a scan that opens or closes one. It carries ids and a count and never a text; the UI reads the list again.

## Limits against clients that hold resources

The server holds at most 256 connections; a further client waits in the backlog of the system until a slot is free. The server speaks HTTP/1 only. A connection that does not finish the head of its request within 10 seconds, also one that sends nothing at all, is closed (hyper's `header_read_timeout`), and the body of a JSON request to a command or to the session routes has 30 seconds, then `API-503` (408); the MCP route is not covered yet (#273). Running commands have no time limit of their own: a scan may take as long as it needs. On shutdown the event streams get a close frame (1001) and open connections have 5 seconds to finish. This stops a client that opens connections and sends nothing, or sends a byte at a time, but is no replacement for a reverse proxy in the server mode of the team server (ADR 0019).

## Effective settings

`settings.effective` (permission `read`, no input) lists every key of `config/default.toml` as it holds for this run: `settings` (`key`, `value` as TOML text, `origin` one of `default`, `user`, `ui`, `project` or `cli`, `hidden`), `user_file` (`path`, `found`; `null` if no location is known) and `overrides` (the `--set key=value` flags of the start). It is read-only and changes nothing. The answer is built once at start from the same files and flags as the configuration of the run (read a second time, so a file edited in that very moment could differ), and a project file is not part of it (it needs a project). A key that has one of the words `token`, `secret`, `password`, `passwd`, `credential`, `credentials`, `private`, `key` or `apikey` in its name is never given out: `hidden` is `true` and `value` is empty, in the flags the value is left out as well. The shipped configuration has no such key; a test fails if it gets one by accident.

## Preferences of the user

`preferences.get` (permission `read`) and `preferences.set` (permission `manage`) keep the theme and the language of the UI in the file `preferences.json` in the data folder, so that every browser of the user shows the same. `preferences.set` replaces both values (`null` forgets a choice); a name must be 1 to 32 characters of `a-z`, `0-9` and `-`, otherwise the answer is `API-101`; an unwritable data folder is `APP-201`. The file is written beside itself and renamed over the old one; a missing, damaged or too large (over 4 KiB) file counts as no choice. The UI reads the values once the session is connected: if the server holds a choice it wins over the copy in the browser, otherwise the choices of the browser (made before the server kept them) are sent. The browser keeps its copy in `localStorage` so that the first paint needs no request. The file holds no secret. With several users (team edition, ADR 0019) the file moves into the user record.

## Saved settings of the UI

`ui_settings.get` (permission `read`, no input) returns what the UI saved in `ui-settings.json` in the data folder: `indexer_memory_mb`, the memory limit in MB per indexer by name (an indexer without an entry has no saved value). `ui_settings.set_indexer_memory` (permission `manage`) takes `indexer` and `megabytes` (a whole number; `null` forgets the saved value) and answers with the saved settings. An unknown indexer or a value above 1,048,576 is `API-101`; an unwritable data folder is `APP-201`. The file is written beside itself and renamed over the old one, like the preferences. The program reads it as a layer of the configuration between the user file and the project file (origin `ui` in `settings.effective`), so a new value counts from the next scan: a scan started in the app reads the configuration anew, and so do the scans an agent starts with `rescan` through the running server (a separately started `codeskimr mcp` reads it at its start), while a scan that is running keeps its value; a missing, damaged or too large (over 4 KiB) file counts as no settings, and a name or value the configuration would refuse is dropped (ADR 0103).

## Configuration

`server.port` (default 7421, must not be 0). `editor.url_template` and `editor.allowed_schemes` (the link of "open in editor"), `ui.default_theme`, `ui.dir` (the folder of the built UI, default `ui`) and `ui.launch_code_seconds` (default 60). A taken port fails with `API-301`. The address is not configurable. `editor.*` and `ui.*` are read from the default, the user file and flags only: the `.codeskimr.toml` of a scanned project cannot set them (ADR 0041). `editor.allowed_schemes` cannot name `javascript`, `data`, `file` or `vbscript` (`CFG-101`). Files below `ui.dir` that are links are not served, and a `ui.dir` outside the data folder is logged as a warning. Every answer carries a `Permissions-Policy` that switches off camera, microphone, location, payment and USB.

## Known limits

- The commands of the UI are registered in `crates/app/src/ui_commands/` (`command_api`): `projects.list` (read), `projects.add` (register_project, scan), `projects.rescan` (scan), `projects.cancel` (scan), `projects.remove` (register_project), `projects.folder_dialog` (read) and `projects.pick_folder` (register_project), `credentials.list` (read_source, the token), `credentials.set` and `credentials.delete` (both register_project), `explorer.outline` and `explorer.symbol` (both read), `search.query` (read), `status.info` (read), `usages.query` (read), `explorer.source` (read_source), `usages.code` (read_source), `graph.layers` (read), `layers.get` (read), `layers.set` (manage), and the annotation and alert commands of ADR 0068 (`annotations.*` and `alerts.*`, see below). Feature packages add theirs there. `layers.get` takes a project id and returns `editable` (a folder project), `scanned`, `layers` (`name`, `namespaces`) and `namespaces` of the newest scan (`name`, `types`, `layer`); `layers.set` takes a project id and the full list of `layers`, replaces the `[[layers]]` tables of the folder's `.codeskimr.toml` (ADR 0065) and answers the number of layers; it refuses a Git project with `PRJ-101`, invalid layers with `CFG-101`, an unreadable or invalid file with `CFG-102` and a failed write with `CFG-104`; the layers apply from the next scan. `rules.show` (read) answers `scanned`, `holdable` (a folder project), `cycles`, `held_on`, `file_version` (a number that changes with the text of the project file; `layers.get` has it too, and `rules.set`, `rules.preview` and `layers.set` take it back as the optional `file_version` and refuse a changed file with `CFG-106`, #811), `rules` (`id`, `kind` one of `layers`, `forbid` and `public_api`, `from`, `to`, `internal`, `reason`, `allowed` (for `layers`: `layer` and `may_use` of every layer that limits its use), `violations`, `new`), `resolved`, `old` and `new`; the layer rule is the first rule if a layer limits what it may use (ADR 0104). `rules.hold` (manage) takes a project id and replaces `.codeskimr-baseline.toml` next to the project file with every violation of the newest scan as an old burden; it answers `{ "held_on": "YYYY-MM-DD", "entries": n }` and refuses a Git project with `PRJ-101`, a project without a scan with `MCP-203`, an unreadable project file or held state with `CFG-101` or `CFG-102` and a failed write with `CFG-104`. `project_file.open` (manage, ADR 0111, REST only, no MCP tool; refused with `APP-605` in a remote or screenless session before anything is created) takes a project id and opens the `.codeskimr.toml` of the folder with the program of the operating system; the path is built from the registered folder and the fixed name, never from the request. A missing file is created empty first, a link or anything but a file is refused with `CFG-102`, a Git project with `PRJ-101`, a failed create with `CFG-104`, and a system that starts no program with `APP-605`; it answers `{ "file": ".codeskimr.toml", "created": bool }`. It is meant for the machine of its user: a server for a team has to switch it off. `unused.keep` (manage) takes a project id, a qualified `symbol` and a `reason` and writes an entry `[[unused.ignore]]` with that symbol into the same file; `unused.lift` (manage) takes a project id and an entry (`paths`, `symbols`, `reason`) and takes the first equal entry out; both answer `{ "entries": n }` and use the errors of `layers.set` (`PRJ-101` for a Git project, `CFG-101` for an invalid entry, a wildcard in the name or an entry that is not in the file, `CFG-102`, `CFG-104`); the entries apply to the statistics at once (ADR 0101). `explorer.outline` takes a project id and returns the layers, namespaces and types of its newest snapshot (the layers of the project; types that belong to none come last with an empty layer name). The answer is short on purpose (#651): a namespace names its most common `language` once, and a type or the file `module` of a namespace leaves out `language` when it is that one, and `qualified_name` when it is the namespace name, a dot and its name (for the module: the namespace name itself; an empty namespace: the name alone); `types` and `holders` are left out when empty and `file` when false. A client puts the fields back by these rules; a field that is present always counts; `explorer.symbol` takes a project id and a symbol id and returns the symbol with `layer` (the name of the layer of the project that owns it, `null` if none does), breadcrumb, metrics (with a rating against the configured thresholds) and member table. An unknown symbol is `MCP-202`. A project without a scan gives `explorer.outline` an empty outline with `snapshot: null`, and `explorer.symbol` the error `MCP-203`. `projects.add` takes an absolute folder path or a Git address without credentials, and for a Git source optionally `credential`, the name of a stored login (`credentials.set`; a folder, an empty name or the installation token gives `PRJ-101`); `projects.rescan` a project id; both take the optional `level2` (`false` scans level 1 only); `projects.rescan` also takes the optional `language`, which limits level 2 to that language (the report keeps the lines of the others) and answer `level2` with `state` (`started`, `not_started` or `not_requested`) and `reason` (`not_permitted`, `not_confirmed`, `busy` or `paused`; ADR 0072): the call returns after level 1 and, if level 2 started, a background task continues with it, still counted as a running scan (`PRJ-302` for a second scan, `projects.cancel` stops it and keeps level 1). The permission and the consent are checked again when the run starts; at most `level2.max_parallel_runs` runs go on at the same time and the same project waits `level2.ui_cooldown_seconds` after a run. Both run the scan on the thread of the call, publish progress on the event bus of the WebSocket and refuse a second scan of the same project with `PRJ-302`. `projects.list` gives every project the files its newest scan left out as `left_out` (`path`, `code`, `kept`; at most `scan.max_left_out_listed`) and `left_out_more` (how many more there were; ADR 0085), and every language of a project `files`, `loc`, `symbols` (the symbols of its files in the newest snapshot) and `tier` (`full` or `basic`, read from the manifest of the installed pack, `null` if there is none). `search.query` takes a project id and a text and returns at most 50 hits of the newest scan, best first, each with kind, qualified name, file, the enclosing symbol and the `project` and `project_name` it belongs to, `files` (at most 10 files whose path matches the text, best first: `path`, `loc`, `first_type` and the project; only files that declare a type) and `entries`, the number of symbols the scan holds (`null` before the first scan); a project without a scan or an empty text gives empty lists. With `all_projects: true` it searches the newest scan of every registered project (`project` is then ignored; projects without a scan are skipped), and each project gets a share of the 50 hits, at least 5. `explorer.source` takes a project id and a symbol id (type or member) and returns the lines of its declaration as they are in the project folder now (`path`, `first_line`, `last_line`, `lines`, `truncated` after 400 lines, `available`) and `spans`: the places in those lines where a symbol is named (`line` counted from 0 within `lines`, `start` and `end` in UTF-16 units, `symbol`), taken from the one-line references of the scan; a place that does not fit its line, because the file changed since the scan, is left out; at most 4000; and `tokens`, the runs of the lines that have a syntax colour (`line`, `start`, `end` as for `spans`, `class` one of `comment`, `string`, `number`, `keyword`, `type`, `function`, `attribute`; ADR 0064; empty for a language without `highlights.scm`). It needs `read_source` and the token (ADR 0035); a Git project answers `available: false` without lines; a file that is gone, outside the project folder or not a file is `SRC-201`, a file over 4 MiB `SRC-501`. `graph.layers` takes a project id and an optional `level` (`layers`, the default, `namespaces` or `types`, see `docs/graph-layout.md`) and, for the level `namespaces`, an optional `depth` (merge the namespaces into their first `depth` segments; 0 or left out keeps them all) and returns the dependency map of its newest snapshot as a picture: `boxes` (one per layer or, on the level `namespaces`, per namespace, with `name`, `x`, `y`, `width`, `height`, `rank`, `order`, `layer` and `types`), `links` (`from`, `to`, `count`, `violates_layering`, `in_cycle`), `bands` (the stripe of every layer row) and the size of the picture (`width`, `height`). The layers keep the order of the project's `layers` setting, outer layers first, one row each (ADR 0031); a layer that only the scan's edges name is added after them. On the level `types` the input needs `focus`, the symbol id of a type: the answer has three rows of boxes (the types that use the focus on top, the focus in the middle, the types it uses below; at most 12 per side, the rest is counted in `focus.users_more` and `focus.used_more`), each with `symbol`, links from the users to the focus and from the focus to what it uses, counted by references; references inside the type are left out, and `bands` is empty. A missing focus or a symbol that is no type is `MCP-202`. A project without a scan or without layers gives an empty picture (`snapshot: null` before the first scan). The positions come from the layered layout in Rust (`docs/graph-layout.md`); spacing and box size are the `[graph]` settings. `graph.modules` (read, ADR 0108) takes a project id and an optional `depth` (as for the namespace level) and returns the module map of the newest snapshot: `boxes`, `bands`, `links` and the size of the picture (one box per module in the row of its layer, at most `graph.max_modules` of them, the most referenced first; `modules_more` counts the rest), `modules` (the table: `name`, `layer`, `incoming` and `outgoing` places, `stability` in thousandths or `null`, `types`, `in_cycle`, `violations`), `cycles` (`modules`, `edges`, and `resolution`, the edges that end the ring, fewest references first), `violations` (dependencies between modules that break the layering, with both layers) and `risks` (a module that `graph.risk_min_incoming` places use and that depends on a module at least `graph.risk_instability_gap` thousandths less stable; at most `graph.risk_max`). Cycles, violations and risks are found among all modules, not only the drawn ones. `usages.query` takes a project id, a symbol id, `way` (`both`, `incoming` or `outgoing`), `depth` (0 means as deep as `mcp.max_depth` allows, larger values are cut to it) and `include_tests`, and returns the symbol, the `incoming` and `outgoing` walks (at most 500 hits each; `null` for a direction that was not asked), a `summary` of the direct usages, the `impact` of a change (symbols reached, layers, public interfaces) and `level2`. Every hit carries `verified`: `true` only if level 2 produced it (an indexer of ADR 0033 ran, with the owner's confirmation, and checked its file); `summary` counts verified and unchecked hits apart, `probable` counts the unchecked ones that level 1 itself is unsure about, and `level2` is `"active"` if at least one direct usage of the answer is verified and `"unavailable"` otherwise, which tells the UI that level 2 checked none of the hits of this symbol. Hits are sorted verified first. Errors as for `explorer.symbol`: `MCP-202` for an unknown symbol, `MCP-203` without a scan. The command needs only the read right, because it hands out no source text. `usages.code` takes the same input and returns `available` and `lines` (`path`, `line`, `text`): the code line of each distinct place of the first 200 hits of both walks, read from the project folder as it is now, trimmed and cut at 240 characters. It needs `read_source` and the token (ADR 0035); the paths come from the index, never from the caller; a Git project answers `available: false`; a place whose file or line is gone is left out. `status.info` takes nothing and returns `version` (the version of the program, as `codeskimr --version` prints it), `startup_ms` (program start until the server answers, `null` if not measured) and `memory_mb` (physical memory of the process, `null` if the system does not tell), `budgets` and `workers` (threads of the analyze stage: one per core the system offers). `projects.cancel` takes a project id and asks its running scan to stop at the next stage boundary; it answers `{ "cancelled": true }`, or `false` if no scan of the project is running (or it has not started yet). The scan then ends without a snapshot: the stream carries `scan_stopped` with `reason: cancelled`, and the call that started the scan (`projects.add`, `projects.rescan`) answers `PRJ-303`. `projects.folder_dialog` takes nothing and answers `{ "available": bool }`: whether the app can show the folder dialog of the operating system on its machine (Windows and macOS; ADR 0075). `projects.pick_folder` takes nothing, shows that dialog, waits and answers `{ "path": "<folder>" }`, or `{ "path": null }` if the user cancelled, no dialog exists here or another one is open; it needs the right to register projects and the token, like `projects.add`, and is no MCP tool. It reads nothing in the folder; the path is only text for `projects.add`. `projects.rename` takes a project id and a `name` and answers `{ "project", "name" }`; it needs the right to register projects, changes only the display name (never id, source, scans or layers) and gives `PRJ-102` for an invalid name and `PRJ-201` for an unknown project; an empty name goes back to the name that the source suggests. `projects.suggest_name` (register_project, not read only, because it looks the folder up on disk) takes a `source` text and answers the `name` it would get, or `null` if the text is no source; the new-project form fills its name field with it. `projects.add` takes an optional `name` (`PRJ-102` if invalid, nothing is registered then). `projects.remove` takes a project id and deletes the project with everything the app stored about it, in one database transaction: all snapshots with their files, symbols, references, metrics and read models, the layers, the level 2 confirmation, the tool reports and the annotations with their alerts; it answers `{ "project": <id> }`. It needs the right to register projects and the token, like `projects.add`, and is no MCP tool. It never touches the files of a folder project. For a Git project it deletes the clone that the app made in its own data folder (`git/<hash of address and branch>`); if the clone cannot be deleted, the project is gone anyway and the failure is logged. Stored credentials stay, because other projects may use the same login. An unknown id is `PRJ-201`; while a scan of the project runs (a level 2 run is part of a scan) it is refused with `PRJ-302`, and while it runs no scan of the project can start. After it, the project can be registered again; it then starts with a full scan. A relative folder path is refused with `PRJ-101`, so the working folder of the server never decides what is scanned.
- No OpenAPI document and no generated TypeScript client yet (needs `utoipa` and real command types, see ADR 0024).
- The UI is part of the program: `build.rs` of the `codeskimr` crate embeds the files of `web/dist` as they are when the program is built (`npm run build` in `web/` first; without it the program has no UI). A folder `ui.dir` that exists wins over the embedded files, so a UI under development can be tried without rebuilding. The embedded files follow the same path rules as a folder. Build order: `web/` first, then the program; without a built UI the build only warns and the program has no UI (release flow: #192). `codeskimr export` takes the export page the same way: from `ui.dir` if the folder exists, else from the embedded files.
- On Windows and macOS the bare `codeskimr` starts a copy of itself in the system tray and ends (ADR 0067): no console window, a tray icon with the menu *Open CodeSkimr*, *Show log* and *Quit CodeSkimr*, the log in `codeskimr.log` in the data folder (empty at every start). `--console` and all other systems keep what follows.
- The bare `codeskimr` (with `--console` on Windows and macOS) starts the server and opens the browser with the launch code (blueprint 10.2); the server keeps running until Ctrl+C, also if no browser could be started. Its start message ends with the hint to keep the window open, because closing it ends the server; the status bar of the UI then shows "Not connected" and the same hint (`status.info` is polled every `STATUS_POLL_MS`; a call without any answer marks the server as gone, any answer marks it as back). `codeskimr serve` and `codeskimr open` remain for the two steps on their own.
- The launch file and the browser start were written for Windows (`explorer`, access rules through `icacls`) and macOS (`open`) and are built there by CI; the access rules and the opener were not run on a Windows or macOS machine by an agent (issue #104 stays open for that check on the real systems).
- No TLS and no non-loopback binding: that is the team server's server mode (ADR 0019).
- A denied command answers like an unknown one (ADR 0044). Two first starts at the same moment are safe: the token file is created under a lock (`token.lock`).
- `serve` needs a usable keystore. On a headless Linux without a Secret Service it stops with `SEC-601`; there is no file fallback (ADR 0045), start a Secret Service such as `gnome-keyring` or `KeePassXC` first.
- Events are not filtered per principal; in single-user mode there is only the local owner.

- `tools.indexers` (scan right, not read only, because it starts version queries as processes; it stores nothing) takes no input and returns the `ToolsView` of all indexers of the language packs, each tool with its `path` where it was found (`docs/tools-check.md`, section "The listing of all indexers"). The rows of `projects.tools` have `path: null`.
- Statistics (ADR 0081), both read-only: `stats.overview` takes a project id and `include_tests` (default `false`) and returns, for the newest snapshot, `files`, `symbols`, `ranked` (the types and callables the rankings hold), `references` (`certain`, `probable`: all counted usages of the snapshot, over every symbol and whatever `include_tests` says), `unused` (`likely`, `public`, `approximate`, `tests_hidden`), `complexity` (`limit` from `metrics.cyclomatic_medium_max`, `over_limit`, `histogram` of `complexity` and `count`) and `top` with the first 5 rows of `most_used` (types), `unused`, `complexity` and `coupling`. `stats.ranking` takes a project id, `ranking` (`most_used`, `unused`, `complexity`, `size` or `coupling`) and optionally `kinds` (`all`, `types`, `functions`), `language`, `include_tests`, `order` (`certain`, the default, or `all`; for `most_used`), `assessment` (`likely`, `public`, `approximate`; for `unused`) and `limit` (default 100, at most 500), and returns `rows`, `total` (the rows before the limit) and, for `unused`, the counts per assessment. A row has `id`, `name`, `qualified_name`, `kind`, `path`, `language`, `parent`, `visibility`, `test`, `certain` and `total` (usages: the certain ones and the upper bound; references of kind `test` and of a symbol to itself do not count), `complexity` with `complexity_rating`, `loc`, `efferent`, `afferent` and `assessment` (only without usages). The ranking `unused` and the `unused` counts leave out constructors and members that are the source of an `override` reference, because they are used without a direct reference. Rows with the same value are ordered by path, name and id. A project without a scan answers `snapshot: null` and empty lists; an unknown project is `PRJ-201`.
- Scan history (ADR 0097), read-only: `scans.list` takes a project id and returns `scans` (the retained scans, newest first, every scan one row, also one that found nothing changed (`files_changed` 0): `snapshot` (the state it wrote or confirmed, shared by scans without a change), `scan` (unique id of the row), `created`, `commit`, `mode`, `files`, `symbols`, `duration_ms` and `files_changed`, both `null` for a scan written before they were stored and `files_changed` also for the first scan of a project), `keep` (`snapshots.retention_count`) and `average_ms` (the mean of the durations that exist, `null` if none does). An unknown project is `PRJ-201`. The answer carries `schema` (1).
- Comparison of scans (ADR 0097, `docs/compare.md`), read-only: `scans.compare` and `scans.impact` take `project` and, optionally, `base` and `target` (ids of kept snapshots, `base` the older; without them the newest scan against the one before it) and answer `schema` (1), `project`, `base` and `target` (a scan as `scans.list` has it), `summary` (`changed_symbols`, `public_symbols`, `usages_certain`, `usages_probable`, `usages_not_touched`; the usage counts are `null` without the impact), the lists `added`, `removed`, `changed` and `moved` (each `total`, `is_cut` and `items`; a symbol has `id`, `kind`, `qualified_name`, `signature`, `visibility` and `path`, a changed or moved one `base`, `target`, `reasons` and `narrowed`), `critical`, `layers` (`new_violations`, `new_cycles`), `impact`, `is_cut`, `direct_usages_only` (always `true`), `note_key` (the Fluent key of the sentence on what the comparison does not see, `compare-direct-only-note`; the screen translates it) and `note` (`null` here). `scans.compare` has `impact` `null`. `scans.impact` has the same answer and in `impact` (`total`, `is_cut`, `items`) the symbols whose usages a change can break: `symbol`, `cause` (`removed` or `changed`), `reasons`, `narrowed`, `usages` (`total`, `is_cut`, `items` with `from`, `path`, `line`, `column`, `kind`, `confidence`, `status` = `adapted` or `not_touched`) and `not_touched`. Errors: `CMP-201`, `CMP-101`, `CMP-301`, `PRJ-201`. `scans.impact_markdown` (permission `read`) takes the input of `scans.impact` and, optionally, `language` (`de` or `en`; without it the language of the saved preferences, then English) and answers `{ "markdown": "..." }`: the text of `codeskimr change --markdown`, made from the answer of `scans.impact` by the same function, which the button "Copy as Markdown" of the screen "Change" puts on the clipboard. It has the same errors.
- `projects.list` rows carry `report` (ADR 0072): `last_scan` (`at`, `level` `"1"` or `"2"`, `origin` `terminal`, `browser`, `watch` or `mcp`) and `level2` (`at`, `origin`, `languages` of `language`, `outcome` `checked`, `skipped` or `failed`, `files` and `stale` for `checked`, `reason` for `skipped`, `code` for `failed`); `null` while no scan stored a report. `usages.query` answers `language` (of the symbol's file) and the same `scan_report`, from which the accuracy card tells apart checked, checked in part, skipped with its reason and failed.
- `projects.tools` (scan right, not read only) takes a project id, runs the tool check (`docs/tools-check.md`), stores it and returns the `ToolsView`. `projects.list` rows carry `tools` (the stored report, `null` if never checked) and `projects.add` and `projects.rescan` answer with `tools` of the scan they ran.
