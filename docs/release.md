# Release process (preview and later releases)

1. Set `version` in the root `Cargo.toml` (for example `0.9.0-preview.1`; `Cargo.lock` follows with `cargo update --workspace`) and update `docs/release/preview-de.md` and `preview-en.md` (the German file is the text of the release).
2. Generate the changelog section and put it on top of `CHANGELOG.md`: `python3 tools/release/changelog.py <version> --since <previous tag>` (for the first release without `--since`). The generator refuses titles with German letters: the titles of squash-merged PRs are English (CLAUDE.md); fix the title of the PR, not the generator (for an old German commit, write the entry by hand). Merge to `main` with green checks.
3. Actions, **Release**, Run workflow, input: the same version without `v`. The workflow checks that the version matches `Cargo.toml`, builds the UI (`web/`, embedded into the program by `crates/app/build.rs`) and the program on Linux, Windows and macOS (Apple Silicon), copies the program with `tools/release/package.sh` to one **single file per system** (`codeskimr-<version>-<platform>`, `.exe` on Windows; UI and language packs are inside), writes its `.sha256`, attests where it was built (GitHub build provenance, `actions/attest-build-provenance`) and attaches both to a **draft pre-release** `v<version>`.
4. Clean-install probe: after packing, the job `clean install (<platform>)` runs on a fresh runner of each system. It downloads the file from the draft like a user, checks the provenance (`gh attestation verify`) and the `.sha256`, puts the file alone into an empty folder and runs it from there (`tools/release/verify.sh`: version, nothing else in the folder, one real scan with the embedded language packs, and the start without arguments as a user does it: the program must keep running, the server must answer with the UI on its start page, and the start message must tell to keep the window open; then the probe ends it). The Linux job runs the probe inside a private D-Bus session with gnome-keyring, because the start needs a Secret Service (`SEC-601` without). A red probe means: do not publish the draft.
5. The product owner tries the files and publishes the draft (this creates the tag). Nothing is public before that.

The files are not signed (decision of the product owner: signing comes first after 1.0, #327). Windows SmartScreen and macOS Gatekeeper warn; the release notes and the manual (`docs/manual/en/installation.md`) explain how to start the file anyway and how users check the SHA-256 sum and the provenance (`gh attestation verify <file> --repo stacknoise/CodeSkimr`). Only the program is a release asset; the manual lives in the repository.

The Node version has one source, `.node-version`. `web/package.json` carries the same version as the program (it is not published on its own).

The checklist for the 1.0 release (milestone M7) is in [`docs/release/checklist.md`](release/checklist.md).
