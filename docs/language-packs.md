# Language packs: how the parsing adapter reads them

`codeskimr_parsing` (WP-23) implements the `FileAnalyzer` port with Tree-sitter. Parsing and extraction are one stage; the syntax tree never leaves the crate (ADR 0013). The pack format follows blueprint 8.1.

## Files of a pack

| File | Required | Purpose |
|---|---|---|
| `language.toml` | yes | metadata and rules (below); unknown keys are rejected |
| `symbols.scm` | yes | declarations to symbols |
| `references.scm` | no | occurrences of names; without it a file yields no pending references |

`language.toml` keys: `id`, `grammar` (built-in grammar name), `tier` (`full` or `basic`), `extensions`, `separator` (inside qualified names), `file_in_names` (default `true`: the path of the file is the first part of every qualified name inside it; `false` for languages with their own namespaces, ADR 0036), `comment_nodes` (node kinds that are comments, used for the line classification), `doc_before_declaration` (list of node kinds, normally attributes, that may stand between the documentation and the declaration: the adapter then takes the run of comments directly before the declaration as its documentation and the query needs no `@doc` capture; use it instead of `((comment)* @doc . ...)` patterns, whose quantifier makes the query very slow on large files, see issue #107), `doc_prefixes` (a comment captured as `@doc` counts only if it starts with one; the prefix is removed), optional `identifier_nodes` and `literal_nodes` (node kinds that syntax fingerprints abstract, see below), optional `manifest_files` and `test_patterns` (read by later stages), `static_keywords` (modifier keywords that make a declaration static), `[modifier_kinds]` (modifier keyword to symbol kind label, for example `const = "constant"`), `[doc_block]` with `open`, `close`, `line_prefix` and optional `stop_at` (block documentation such as JSDoc: the text between the delimiters without the line markers, up to the first line that starts with `stop_at`; without `doc_prefixes` only such blocks are documentation), `[doc_summary]` with `open` and `close` tags (the doc of a symbol is the text between them, whitespace collapsed; without the tags the whole comment) and the table `[visibility]`: `default`, `keywords` (keyword text to visibility label; several keywords together, such as `protected internal`, may have an entry of their own) and `parent_defaults` (parent symbol kind label to the visibility of a declaration without keyword) and `unrated_kinds` (kinds without any visibility, such as namespaces).

## The `[indexer]` table (ADR 0033, level 2)

A pack may name the indexer that gives level 2 references. The table holds everything language specific about running it, so that no command line, version or install hint is in code:

- `name`, `install_hint` (shown when the tool is missing; the user installs, CodeSkimr never does), `args` (the arguments; `{project}` is the folder of the project, `{output}` the index file the indexer must write, and one argument must contain it; the indexer runs with the project folder as its working folder), `env_allow` (names of variables the indexer needs besides the base list of the runner, such as `DOTNET_ROOT`) and `env` (variables set to a fixed value, such as `RUSTUP_AUTO_INSTALL = "0"`, which stops the `rustup` proxy from downloading a toolchain).
- `[indexer.tool]` with `program` (a bare name, looked up in the `PATH` of the user and never in the project), `version_args` and `min_version`, and one `[[indexer.toolchain]]` per tool that must also exist (SDK, runtime) with the same three keys. The version is the first number sequence with a dot in the output of `version_args` (standard output and standard error).
- A pack without `[indexer]` stays on level 1 (Go and the basic-tier languages). TypeScript, JavaScript and TSX name the same indexer; Java and Kotlin too.

**Provisional.** The command lines and minimum versions are those of the indexers' own documentation and have not been run against real installations of every language in CI; the first run in each language is part of the acceptance (ADR 0033, decision 14). `docs/level2-runner.md` says how they are run.

## Capture vocabulary

- `symbols.scm` (a declaration found by several patterns is stored once): `@symbol.<kind>` marks the whole declaration (`<kind>` is a symbol kind label such as `class` or `enum_member`), `@name` its simple name (required). Optional: `@modifier` (may repeat; every modifier keyword, the pack decides what each one means), `@visibility` (like `@modifier`), `@static`, `@doc` (may repeat; lines are joined), `@signature` and `@scope_end` (the node whose end closes the scope of the declaration, for a file-scoped namespace that holds the rest of the file). `@container` marks a block that is no symbol but whose members belong to the type its `@name` names (a Rust `impl`, ADR 0039): the members get the qualified name `<scope>::<Type>::<member>`, the type declared in the same scope before the block is their parent and stands for the block in references from its head (`implement`, type uses); if there is no such type, only the name carries it and the parent stays the enclosing symbol. Several matches of one declaration are merged, so repeated captures such as `(modifier)* @modifier` are safe.
- `references.scm`: `@reference.<kind>` marks an occurrence (`<kind>` is a reference kind label). `@name` narrows the target text; without it the marked node is the target. Further captures give the resolver what it cannot see in a tree (ADR 0013), see `docs/references.md`: `@receiver` (name), `@receiver.type`, `@receiver.member` (a field or property behind `this.`), `@receiver.own`, `@receiver.base`, `@receiver.other` (together with `@name`, no `@reference`: the receiver in front of a member name), `@local` and `@field` (name of a declaration), `@declared_type` (its type name) and `@scope` (node in which declared names are visible).

A capture outside this vocabulary, an invalid query or an unknown grammar fails the load with `PRS-301`.

## Results

- One `module` symbol per file; every declaration is nested below the innermost enclosing declaration. With `file_in_names = true` (Rust, Python, TypeScript, JavaScript) the qualified name of the module is the path without extension, folders joined with the separator, and every name below starts with it. With `false` (C#, Java, Kotlin, ADR 0036) the module keeps the path with its extension (`app/Calculator.cs`, which no type can be called), and the names below start at the namespace: `Demo.Calculator.Add`. Two symbols can have the same qualified name (a type in two files); the id tells them apart. The scan records the naming rules of the packs with the snapshot; an incremental scan after other rules, or after a snapshot from before the record, is a full scan. The record lists every installed pack, so installing a new pack also causes one full scan. For partial types (the same qualified name in several files) the type focus assigns members to one of them, the one with the highest id; a separate issue tracks assigning by parent.
- Pending references point at the innermost enclosing symbol; occurrences outside any declaration belong to the module.
- `loc` counts lines that contain at least one non-comment token. Lines inside multi-line tokens (strings) count as code.
- Failures: `PRS-101` (encoding; UTF-8 and UTF-16 with BOM are read), `PRS-201` (no pack), `PRS-301` (invalid pack), `PRS-501` (parse timeout), `SRC-201` (file cannot be read).
- Constants without a `@signature` capture get their whole declaration as signature (`find_constants` shows the value): `const LIMIT: usize = 10;` in Rust, `MAX_SIZE = 10` in Python, `const val MAX_SIZE = 10` in Kotlin. Packs that deliver the full declaration (type, modifiers, value): Rust, Python, Kotlin, C#, Java (`@signature` on the field declaration; with several declarators in one declaration, `static final int A = 1, B = 2;` or `const int A = 1, B = 2;`, each constant gets the whole declaration). Where the grammar's declaration node is the declarator only (TypeScript/JavaScript) the signature is `name = value` without type and modifiers. A signature is at most `scan.max_signature_chars` characters (default 400); a longer one is cut and ends with `…`.

## The C# pack (WP-24)

`languages/csharp/` is the first real pack (full tier). `language.toml` documents the mapping onto symbol kinds. Decisions worth knowing:

- Qualified names start with the file module (`Folder.File.Namespace.Type.Member`), like every pack.
- `protected internal` and `private protected` count as `protected` (the domain has no combined value). A top-level type without keyword is `internal`, a member without keyword `private`, a member of an interface or enum `public`.
- A positional record parameter is a `public` property. A `const` field is a `constant`. A delegate is a `type_alias`. Not symbols: parameters, locals, lambdas, finalizers, conversion operators, primary constructor parameters of classes.
- The doc of a symbol is the text of its `<summary>`; inner markup such as `<see cref="X"/>` stays as written. A comment without `<summary>` (for example `<inheritdoc/>`) is kept whole.
- `references.scm` is level 1 (names, receivers, locals and scopes). `new Foo()` is a type use; a base type is `inherit` (the resolver can refine it to `implement`); reads are reported for names in value positions and for receivers of member accesses.
- `metrics.scm` holds the captures of ADR 0015 (`@comment`, `@decision`, `@operator`, `@operand`). The adapter runs it once per file; `tests/csharp_metrics.rs` and the golden files (`counts`) check one case per counting rule. `highlights.scm` is for the UI.
- Golden tests: `languages/csharp/tests/*.cs` with the expected result in `<file>.json` (`CODESKIMR_BLESS=1 cargo test -p codeskimr_parsing --test language_packs` rewrites them; review the diff).
- Corpus: `corpus/csharp/corpus.toml` pins a public project (ADR 0016); `tests/corpus.rs` fetches it into `target/corpus/` with `git` and compares counts and a hand-checked sample. `CODESKIMR_CORPUS_DIR` points the test at another checkout (for the private reference: only locally; `CODESKIMR_BLESS=1` prints the counts per kind and the `SUMMARY` line of the counting rule in ADR 0017).

## The Rust pack (WP-65, ADR 0026)

`languages/rust/` is a full-tier pack; `language.toml` documents the mapping. Decisions worth knowing:

- Qualified names use `::`. `mod` is a `namespace`, `trait` a `trait`, `union` a `union`; `const` and `static` are `constant`s; named fields are `field`s. A function in an `impl` or a trait is a `method` (static without `self`), any other one a `function`. There is no constructor kind.
- `impl` blocks are containers, not symbols (ADR 0039): their methods are `mod::Type::method` and children of the type if it is declared earlier in the same module, and the `implement` reference of `impl Trait for Type` comes from the type, so the resolver can build the hierarchy. Limits: an `impl` before its type, in another module or file, or with a head that is not a plain or generic type name (`&Type`, `a::Type`) keeps the type only in the names (or has no container at all), and the hierarchy of such a type stays incomplete.
- Visibility from `pub`, `pub(crate)`, `pub(in path)`, `pub(super)`; trait members, variants and functions of trait implementations are public. Documentation is `///` and `/** */`, attributes may stand between.
- Declarations are queried by patterns of their own for the name, the documentation, the visibility and `static`, because a quantified comment inside a parent pattern only matches the first declaration of the list (see ADR 0026).
- Golden tests: `languages/rust/tests/*.rs`, `tests/rust_metrics.rs`. Corpus: `corpus/rust/corpus.toml` pins CodeSkimr itself, counts checked with `syn`.

## The basic tier (WP-66, ADR 0020)

`languages/go`, `c`, `cpp`, `ruby` and `php` are basic-tier packs (`tier = "basic"`): types, namespaces and functions with their spans, lines of code, decision points for CC (`metrics.scm` with `@comment` and `@decision`, no Halstead counts, so no MI), calls as references by name and syntax fingerprints. No doc comments and no visibility. Adding a language is a folder of data plus one dependency, one name constant and one line in `grammar.rs` (the exception to blueprint 8.2 that ADR 0020 records).

- **Loading.** `LanguagePacks::load` reads the `language.toml` of a basic pack only. Grammar and queries are compiled when the first file of the language is analyzed; `LanguagePacks::iter` returns a `PackSummary` (id, tier, extensions) without loading anything. A full-tier pack is loaded at once.
- **Feature.** The basic grammars are optional dependencies behind the cargo feature `basic-grammars` (default on). Without it a basic pack fails with `PRS-301` when it is first needed.
- **Showing the tier.** `PackSummary::tier` and `LanguagePack::tier` carry the tier for the language table of the scan screen and the explorer; `codeskimr_parsing::tiers(root)` reads the tier of every pack from the manifests alone (no grammar, no query), which is what `projects.list` uses; the screens themselves are separate packages.
- **Mapping.** Go: `struct`, `interface` and every other `type` as `type_alias`, `func` as `function`, a function with a receiver as `method` (named `<file>.Method`: the receiver type is not part of the name, so two methods of that name in one file collide, issue #65). C: `struct`, `union`, `enum` and `typedef` of those (as `type_alias`) where they have a body, `function`. C++: also `class` and `namespace`, a function in a class body (also a member template, constructor, destructor or operator) or written as `Class::name` is a `method`; a method written outside its class does not carry the class in its name (issue #65). A second `namespace X;` without braces in PHP nests into the first (issue #65). A `def` directly inside a top-level or class-level `if`, `unless` or `begin` is found in Ruby (deeper nesting is not), and C functions that return a function pointer are found. A basic pack that cannot be loaded fails once per run: the first failure is remembered, so the other files of the language do not build it again. Ruby: `class`, `module` as `namespace`, `def` in a class or module as `method`, a top-level `def` as `function`. PHP: `class`, `interface`, `trait`, `enum`, `namespace`, `function`, `method`. `.h` belongs to C, not to C++.
- **Golden tests.** `languages/<lang>/tests/sample.<ext>` with the expected result next to it, like the full tier. The samples are written for this repository; no foreign code is copied.

## Syntax fingerprints (WP-34)

`TreeSitterAnalyzer::with_fingerprints(&config.similarity)` turns fingerprinting on; `FileFacts::fingerprints` then holds one entry per function, method or constructor with at least `similarity.min_tokens` tokens. The declaration is flattened into leaf tokens: comments are dropped, nodes listed in `identifier_nodes` all become one identifier token, nodes in `literal_nodes` become one literal token (and are not descended into), everything else keeps its node kind. The domain function `winnow` hashes all n-grams of `similarity.ngram_size` tokens and keeps the minimum of every window of `similarity.window_size` hashes. A shared run of `window_size + ngram_size - 1` tokens always yields a shared fingerprint. `Fingerprints::similarity` (Jaccard) and `containment` compare two bodies; `find_similar_code` and the duplicate check of `check_conventions` use these same functions. The hash is implemented in the domain (no new dependency, values stable across releases). A pack without the two keys still fingerprints, but names and values then influence the result. Persisting the fingerprints and the queries on top are separate packages.

## Metric counts (`metrics.scm`)

`FileFacts::counts` holds one `SymbolCounts` per callable, type, namespace and module of the file: the code lines of its span and, for a callable with a body, the decision points and the Halstead counts. The adapter assigns every capture of `metrics.scm` to the innermost callable symbol that contains it, so a lambda counts for its enclosing callable and a named local function for itself; captures outside any callable (field initialisers) count for nobody. A node captured by two patterns counts once. A callable has a body if its declaration node has the grammar field `body`; abstract, interface and extern members have none and get no `cc` and no `mi`. The `loc` of a callable leaves out the lines of its local functions and local types. The `loc` of a type, namespace or module is the full span of the symbol, including its callables: it counts the code lines of the whole declaration, and subtracting local functions only applies to the callable that declares them. `@comment` is accepted in `metrics.scm`, but the line kinds come from `comment_nodes` in `language.toml`. A pack without `metrics.scm` delivers lines only and therefore only `loc`.

The `StandardMetrics` calculator (`codeskimr_application::metrics`) turns the counts into `loc`, `cc`, `cc_max` and `mi` with the pure functions of `codeskimr_domain::metrics` and rolls them up to types, namespaces and modules (`codeskimr_domain::measure`, ADR 0015): `cc` is summed, `cc_max` is the highest callable value, `mi` is the mean weighted by the callables' lines of code. Coupling (Ce, Ca, instability) of namespaces and modules is computed by the same calculator from the references of the whole snapshot (`codeskimr_domain::coupling`, ADR 0037); it needs nothing from the language pack.

## Not part of this package

The parse time limit comes from `scan.parse_timeout_ms` (default 5000), wired by the composition root (WP-25, closes #32).

## Project version files (`requirement` of `[[indexer.toolchain]]`, ADR 0033 decision 8)

A toolchain entry may carry `requirement = { file, format, path }`: the file of the project that names the version it needs (`format` is `json`, `toml` or `text`; `path` is the key path for json and toml, such as `["sdk", "version"]`). The check of the tools (`docs/tools-check.md`) raises the pack's `min_version` of that program to it when it is newer; the runner ignores it. The purpose and install hint of every program are Fluent keys `tool-<program>-purpose` and `tool-<program>-install` in `locales/`. The adapter reads only the manifests (`PackTools`).
