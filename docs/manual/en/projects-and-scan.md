# Projects and scan

A **project** is a source that CodeSkimr knows: a folder on your machine or a Git repository. A **scan** reads the source and stores the result as a **snapshot**. Browsing, search, usages and MCP always answer from the newest snapshot. CodeSkimr keeps the last five snapshots per project.

## In the browser

The first screen has the list of your projects on the left (state dot, name, main language and last scan; a thin bar while a scan runs; a filter field) and the page of the selected project on the right. The page has five tabs: **Overview** (types, lines, files, the languages with their accuracy in words, the last scan, the tools and the database file of the project with its path and size), **Scan** (progress, steps, languages, files left out), **Scope** (which languages and folders are covered), **Exact check (stage 2)** and **Tools**. The button "New" (key `N`) opens the form for a new project.

- **Add a project:** press "New" or key `N`, then type or paste an absolute folder path or a Git address into the source field and confirm. A folder or a text dropped on the window goes into the field; some browsers do not reveal the path of a dropped folder, then the screen asks you to paste it.
- **Choose the folder with a dialog:** on Windows and macOS the button "Browse …" next to the field opens the folder dialog of your system. The chosen path appears in the field; click "Add and scan" to add it. Without a dialog (for example on Linux) type or paste the path.
- **Open a project:** select it with the arrow keys or the mouse and press `Enter` or the button "Open in explorer". It becomes the active project that the explorer, the dependency map and the usages screen show.
- **Scan again:** the buttons are in the tab "Scan" of the project page; the key `R` opens that tab for the selected project. While a scan runs the state reads "scan running", the page shows the tab "Scan", and "Cancel" appears at the top right (`Esc`; if a name edit or the question before a removal is open, `Esc` closes that first).
- **Name a project:** the small window "New project" (button "New" at the top of the list, or the key `N`) has the field "Display name", filled in for you; a folder called `src` becomes `shop/src` after its parent, so many projects named `src` stay apart. Type another name if you like. Later, the pencil icon on the page of the project changes it (empty = back to the suggested name); on the command line use `codeskimr scan <folder> --name "My shop"`. The name is only a label: the folder, the scans and your notes stay. It is at most 80 characters; otherwise `PRJ-102`.
- **Remove a project:** the bin icon on the page of the project (not while a scan of the project runs). A window names what is deleted and what stays, and asks once ("Remove for good" or "Cancel"; `Esc` cancels). Afterwards the project, all its scans and results, the level 2 confirmation, the tool check and your notes and marks are deleted from CodeSkimr. **Your files stay untouched**: for a folder project nothing in the folder is deleted, for a Git project only the copy that CodeSkimr made in its own data folder is deleted. Stored credentials stay, because other projects may use them ([Sources and credentials](sources-and-credentials.md)). If it was the active project, none is active afterwards. You can add the same source again later; it is then scanned in full. If a scan of the project is running, the removal is refused with `PRJ-302`: cancel it or wait first.
- **Tools for level 2:** the tab "Tools" names every missing or too old indexer tool, why it is needed and how to install it, with a button "Check again" ([Language indexers](indexers.md)). It never blocks a scan.
- **Report of stage 2:** the tab "Scan" lists what the last stage 2 run did, grouped: failed, skipped, checked. If stage 2 is off or not confirmed for the project, one hint names the languages it would check, without a button each. Languages that no indexer covers (for example C, C++ and Ruby) stand in their own group "No stage 2 available": their references stay approximations from stage 1. The button "Check again" in a row checks that language only.

The same source is registered only once. Two scans of the same project cannot run at once (`PRJ-302`).

A relative folder path is refused (`PRJ-101`), so the folder the server happens to run in never decides what is scanned.

## The tab "Scan" and the performance targets

The tab "Scan" of a project shows the scan that is running or ran last: the stage it is in (fetch source, find files, parse, resolve dependencies, metrics, save, and stage 2), files and lines per second, cores in use, memory, and a table per language with tier, files, symbols and parse time. You can watch the scan of any project in the list, also while several run. The page jumps to the tab when a scan of the selected project starts. The old screen "Scan and performance" is gone; its address leads to this tab. The entry **"Performance"** in the status bar opens the list of performance targets: it compares measured values of the program with its budgets (program start, search per keystroke, switching a type, usages query, map layout). The targets are those of the whole program, not of a project.

The first scan of a project is full. Later scans are **incremental**: files are compared by a content hash and only changed files are read again; a scan after a small change finishes in a fraction of a second. The button **"Full scan"** in the tab "Scan" of the selected project reads every file again instead, as `codeskimr scan` does on the command line. The interface stays usable during a scan, and you can **cancel** a running scan with the button "Cancel" or `Esc`; it ends without writing a snapshot.

## On the command line

```
codeskimr scan <path|git-url> [--branch <name>] [--json] [--watch] [--credential <name>]
```

- The argument is an existing folder or a Git address (`https://`, `http://`, `ssh://`, `git://`, `file://` (a local repository), `git@host:org/repo`, or ending in `.git`). A folder is made absolute. `--branch` only applies to Git sources and defaults to `main`.
- The command registers the source as a project (once) and runs one full scan. The result is a two-line summary, followed by one line for each missing or too old indexer tool and, if you enabled it, one line per language for level 2 ("checked" or "skipped (reason)"). With `--json` it is one JSON line: `{project, snapshot, files, symbols, references, seconds, tools}`.
- **`--watch`** keeps the command running after the first scan. When files in the folder change, they are collected for a short moment and scanned again incrementally; each re-scan prints one line. Only folders can be watched (`CLI-102` for a Git address). Stop with Ctrl+C. A failed re-scan prints its error and watching goes on.
- **Secrets in a Git address** (user name and password, a token, a query or a fragment) are refused with `PRJ-101`. See [Sources and credentials](sources-and-credentials.md) for the right way (`--credential`).

The bare `codeskimr` starts the server and opens the browser. On Windows and macOS it runs in the system tray: the console window can be closed, and the icon has a right-click menu to open the browser again, show the log (`codeskimr.log` in the data folder) and quit. `codeskimr --console` stays in the window instead; so does Linux. Other commands: `codeskimr level2 confirm|revoke` allows or forbids indexers for a project ([Language indexers](indexers.md)), `codeskimr credential` manages Git logins ([Sources and credentials](sources-and-credentials.md)), `codeskimr annotations` and `codeskimr alerts` manage notes, tasks, critical marks and their alerts ([Notes, tasks and critical marks](annotations.md)), `codeskimr serve` starts the local server, `codeskimr open` opens the browser (`--no-browser` only writes the launch file and prints its path; `--no-browser --print-url` prints an address with a one-time code instead, for remote browser tests that cannot open `file://` pages. The code works once and only briefly, but it is then in your terminal or log: use it only where nobody else reads along), `codeskimr mcp` starts the MCP server on standard input and output ([MCP setup](mcp.md)), `codeskimr export` writes a project as one HTML file ([HTML export](export.md)), and `codeskimr check` runs the convention checks over a folder without a scan.

Global options for all commands: `--data-dir`, `--languages`, `--config` and `--set key=value` (see [Installation](installation.md)).

Exit codes: `0` success, `1` a command failed (`error[CODE]: text` on standard error) or `check` found violations, `2` invalid arguments (`CLI-101`).

## What a scan skips

Files that `.gitignore` excludes (also outside Git repositories), the folders in `scan.excluded_folders`, the `.git` folder, and files of unknown languages (they do not count against the size limit). Limits: a project over `scan.max_source_mb` (default 2048 MB) fails with `SRC-501`; a single file that takes longer than `scan.parse_timeout_ms` (default 5000 ms) to parse is skipped (`PRS-501`). Signatures (for constants the whole declaration with the value) are limited to `scan.max_signature_chars` characters (default 400); longer ones are cut and end with `…`. For very large projects `scan.max_candidates` (default 100) applies as well: a place in the code that reaches more symbols through its name alone (for example `x.id` or `.dispose()` on a value of unknown type) is not given to all of them but counted and reported as warning `RES-304`; places that scope, type or imports narrow down are never affected, and level 2 gives exact results there. A smaller value makes the scan of large projects faster and smaller. So that a project that is too large does not end the whole program, CodeSkimr watches the memory during a scan: if the scan holds more than `scan.max_memory_mb` (default 16384, at most 70 % of the installed memory), it is stopped with `PRJ-503` and stores nothing. A `.codeskimr.toml` inside a scanned project can lower these four limits (`scan.max_source_mb`, `scan.parse_timeout_ms`, `scan.max_candidates`, `scan.max_memory_mb`) but not raise them; only your own config file and command line flags can. A file that is not valid text (`PRS-101`) is skipped too, and so is a file that disappears or is locked during the scan (`PRS-102`). The scan goes on in all three cases. The summary of `codeskimr scan` and the answer of the MCP tool `rescan` name the files left out with path and code, at most `scan.max_left_out_listed` (default 20), and count the others; the tab "Scan" lists the same files of the newest scan, each with its code and whether it is missing in the result or shown as the previous scan saw it (the message of a code once, with its first file), and says how many more there were (the list belongs to the scan and is replaced by the next one); the log names each one (`scan_file_skipped`). What the result shows of a file left out: with a wrong encoding the file is missing in the result; if it was valid text in the previous scan, its symbols count as removed, and critical marks in it report that. After a parse timeout or an unreadable file every scan, a full scan too, keeps the state of the previous scan, so that symbols, notes and critical marks do not vanish because of a short disturbance; the next scan tries the file again. A full scan that keeps such a file is stored and counted as an incremental scan (`mode` is `incremental` then). If there is no previous scan, or the naming rules of the language packs changed since, the file is missing in the result. If not a single file remains (a project saved entirely in Windows-1252, say), the scan fails with the code of the first file left out instead of storing an empty result. A scan analyses files on one thread per core; `scan.max_workers` (default 0, meaning all cores) sets a lower limit, for example to leave cores to a build that runs next to the scan. `scan --json` reports `cpu_seconds` (CPU time of all threads) and `pack_load_seconds` (time spent loading language packs, which `seconds` leaves out) next to `seconds`. The memory limit `scan.max_memory_mb` takes the value of the configuration at program start; a value in `.codeskimr.toml` (lowering only) counts for scans in the terminal and by the MCP server, not in the app.

## Layers

CodeSkimr shows your architecture as **layers**. You declare them in the file `.codeskimr.toml` in the root of the scanned folder:

```toml
[[layers]]
name = "Domain"
namespaces = ["Shop.Domain"]

[[layers]]
name = "Application"
namespaces = ["Shop.Application"]

[[layers]]
name = "Infrastructure"
namespaces = ["Shop.Infrastructure", "Shop.Data"]
```

`namespaces` are qualified-name prefixes; the separator is `.` or `::`. A name belongs to the first layer whose prefix matches. List outer layers first: the dependency map draws them on top, one row per layer. Layers apply at the next scan. A layer may also list the layers it is allowed to depend on: `may_use = ["Domain"]`. A dependency on a layer that is not listed counts as a violation on the [dependency map](dependency-map.md). Without `may_use` a layer has no limit; an empty list means it may use no other layer; an unknown layer name is refused with `CFG-101`. Without layers the explorer groups everything under an empty layer and the map is empty.

### Setting layers in the UI

You do not have to write the file by hand. On the screen **Layers** (left bar; also through the hint in the explorer and on the empty dependency map) CodeSkimr shows the namespaces of the last scan as a tree. Tick the namespaces that belong together (a tick counts with everything below it), name the layer and create it. Reordering, renaming and taking namespaces out is done in the list on the right. **Save and scan again** writes the `[[layers]]` blocks into the `.codeskimr.toml` of your project folder and scans the project again, after which the layers apply. Only these blocks are replaced; everything else in the file stays, and so does `may_use` for layers of the same name. Comments inside the old `[[layers]]` blocks are lost. CodeSkimr proposes nothing itself: layers only come from your choice. A Git project has no project folder; add the layers in the repository there. What each layer may use (`may_use`) is set on the screen **Rules**, see [Rules](rules.md).


## Scope of a project

A project can leave out languages and folders (ADR 0102). With no entries everything is covered; new languages and folders are included automatically. A folder that is left out takes everything below it with it. On the console `codeskimr scope <project>` shows the scope with the file counts; `--without-language`, `--with-language`, `--without-folder`, `--with-folder` and `--reset` change it. A change applies from the next scan; files that leave the scope then count as removed files. Folders that `.gitignore` or `excluded_folders` already hide are not offered in the overview. An invalid scope is refused with `PRJ-103`. Loading the same code twice into two projects stays allowed.

In the browser you set the scope in the tab **Scope**: languages as chips, folders as a tree, with file counts. A folder with a project file (`package.json`, `Cargo.toml`, `.sln`) carries the note "Level 2"; it uses the exact check in the same project, so a project of its own is not needed for that. As soon as you change something, a box shows what disappears with the next scan; "Save & rescan" saves and starts the scan. If you enter a folder in the window "New project" that already lies inside a project, a hint says so: you can cover it in that project (the default) or still add it as a project of its own.
