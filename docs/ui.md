# Browser UI (WP-42)

SolidJS, TypeScript and Vite in `web/`. Decisions: ADR 0028 and ADR 0030.

## Develop

```
cd web && npm ci
npm run dev                   # vite build --watch, writes web/dist
codeskimr --set ui.dir=web/dist serve
codeskimr open
```

## Checks

`npm run typecheck`, `npm run lint`, `npm run format`, `npm test` (Vitest) and `npm run e2e` (Playwright against the real server, needs Chromium; `CODESKIMR_CHROMIUM` can point to a binary).

## Structure

- `src/shared`: API client, session (launch code exchange, token in `sessionStorage`), theme store, texts (Fluent files from `locales/`), editor link, small UI parts.
- `src/features`: settings (theme cards with preview, language, editor), connection screen, projects (screen 1, WP-44), explorer (screen 2, WP-45), usages (screen 6, WP-53).
- Themes Hell, Petrol (default) and Dunkel are CSS variables generated from `design/tokens.toml` by `cargo run -p codeskimr_codegen`; never edit the generated files.
- No literals in the code: values live in `consts.ts` files, texts in `locales/`.

## Projects (screen 1, WP-44)

The screen calls four commands over `POST /api/v1/commands/{id}` (`shared/api/commands.ts`): `projects.list`, `projects.add`, `projects.rescan` and `projects.remove` (see `docs/server.md`). `projects.rescan` scans the changes since the last scan; with `full: true` (the button "Full scan" of the scan section) it reads every file again, as `codeskimr scan` does.

- `projects.ts` keeps the list, the failure of the last action and the scans started in this tab. While a scan runs, the list is read every 1.5 s, so a running scan shows up as "scan running".
- Keys: `N` focuses the source field, arrow keys move the selection, `Enter` opens the project (it becomes the active project, `shared/project/active.ts`, and the explorer is shown), `R` scans it again. Typing in a field and Ctrl, Alt or Meta combinations never trigger them.
- Browse: next to the source field, if the source is a folder and `projects.folder_dialog` says a dialog exists (Windows and macOS, ADR 0075, mock 19), the button "Browse …" opens the folder dialog of the operating system through `projects.pick_folder`. While it is open the form shows "Folder dialog open" with "Stop waiting"; a chosen path goes into the field with a note to check it, nothing is added before "Add and scan". Without a dialog there is no button.
- Remove: every row has a "Remove" button next to the status (not while a scan of the project runs). The first click turns it into the question "Remove … from the app?" with "Remove for good" and "Cancel" (two steps in the row, no `window.confirm`); the second one calls `projects.remove`, reads the list again and, if the project was the active one (`shared/project/active.ts`) or the selected row, clears that. What this tab keeps per project (tool check, scan time, level 2 state) is dropped too, because a new project can get the id of a removed one. A failure (for example `PRJ-302`) shows its message in the usual place below the form; the project stays. The text says that scans, results and notes are deleted and the files stay.
- Drop: a `file://` address or text dropped on the window goes into the source field. A browser does not tell the path of a dropped folder in every system; the screen then says so and asks to paste the path.
- Effective settings (settings, mock 21 `docs/mocks/EffectiveSettings.html`, screenshots `docs/screenshots/effective-settings/`; the console counterpart is `--set` and `config.toml`, see `docs/cli.md`): the last section of the screen lists every key of `config/default.toml` with its value and where the value comes from: default, `config.toml` (user file), project file or command line (`--set`). It asks `settings.effective` when the screen opens. The list is grouped by table, can be searched by key or value, and a switch narrows it to the values that differ from the default. It is read-only (no button changes anything) and shows no secret: a key with one of the words `token`, `secret`, `password`, `passwd`, `credential`, `private` or `key` in its name would be listed as "hidden" with no value (the shipped configuration has none). The values come from the files and flags of the start (read again for this list at start, so a file edited in the same instant could differ); the file of a project is not part of the list. The word list for secret keys splits a key at `.`, `_` and `-`.
- Indexer listing (settings, mock 17): the section below the layer editor shows every indexer and toolchain tool of the language packs with state, version, path, the error line of a tool that does not start and, for a tool that is not ready, the install text with a button that copies its command; "Check again" asks `tools.indexers` (see `docs/tools-check.md`). It checks when the screen opens.
- Tool check: the screen also calls `projects.tools` for the selected project. `ToolsPanel` shows a warning (`role="status"`) with every missing, not runnable (found, but it crashes on start; the panel shows its error line), too old, too new or unreadable tool, its purpose, the install hint, the languages that are ready and a "Check again" button; the project table shows a warning pill "N tools missing", which counts every tool that is not ready, `not_runnable` included. Both are additions to the mock (see `docs/tools-check.md`); the state `too_new` adds one text to the existing status label of the tool warning (the pill keeps saying "missing") and changes no layout, so there is nothing new to compare with the mock. Deviations from the mock: a small "scan again" button sits next to the status pill (so the re-scan has a mouse path, not only the key R); the status "new commits" and the scan duration of earlier sessions are missing because the data model has neither (the duration of scans started in this tab is shown); language colours come from the layer tokens.

### Level 2 switch (ADR 0071, mock 18 `Level2Switch.dc.html`)

A column "Level 2" with a switch (`role="switch"`) per project and a section under the table for the selected project. The state comes from `level2.status`; switching on posts to `/api/v1/level2/confirm-window` and then only asks the state again (`ui.level2_poll_seconds`, default 2, at most `ui.level2_poll_max_seconds`, default 300). The page never gives the consent. Switching off asks once and calls `level2.revoke`. While the page waits, "Cancel waiting" (or Escape, on the switch or in the section) ends the wait at once: the asking stops, the notice goes and the focus returns to the switch; the page cannot see that the console window was closed, so this and the time limit are the only ways out. The time limit is its own timer (`ui.level2_poll_max_seconds`), independent of the questions, and ends in "not confirmed, you can try again" with the focus on the switch; the notice also says that a pause of 30 seconds applies after a window was opened and that a click too early is answered with `API-504`. Without a window (`launch: copy`, or `APP-604`) the command `codeskimr level2 confirm <id>` is shown with a copy button. `not_enabled` only shows the two lines for `config.toml`; nothing is written. Mock 1 does not show the switch, so mock 18 was added; the e2e test `ui-level2.spec.ts` fakes the three level 2 calls until the backend package is merged.

## Explorer (screen 2, WP-45)

The screen shows the active project (`shared/project/active.ts`) with two commands: `explorer.outline` (the tree) and `explorer.symbol` (one type with breadcrumb, metrics and member table); both need only the read right (see `docs/server.md`). The source column (WP-45b) adds `explorer.source`, which needs `read_source` and the installation token (ADR 0035). Screenshots: `docs/screenshots/explorer-hell.png`, `explorer-petrol.png`, `explorer-dunkel.png`.

- Tree: layer (with its colour dot), namespace, type (nested types are rows below their type), then the groups "Fields etc.", "Methods" and nested types with their members. The tree is virtualised: only the rows in view (plus a margin) are in the DOM. It is one `tree` with `aria-activedescendant`; the group rows are expandable `treeitem`s as well. Click rules (blueprint 15.4): the caret only opens and closes; a click on an unselected type selects it; a click on the selected type opens or closes it; groups open and close on their own; selecting from inside the tree never changes what is open; at the start everything is closed and the overview is shown. The filter keeps the types whose name contains the text, with their layer and namespace opened.
- Click rules: ADR 0038 settled issue #140: the first click on an unselected type only selects it (blueprint 15.4 says so now). The rows carry `aria-level`, `aria-setsize` and `aria-posinset` counted over the whole tree (`siblingPlaces` in `tree.ts`), so a screen reader announces the real place although only the rows in view are in the DOM.
- Keys: Up and Down move the cursor, Right opens (or goes to the first child), Left closes (or goes to the parent), Home and End jump, Enter and Space select or toggle, `Ctrl+Left` closes everything, `Ctrl+.` shows the selection.
- Tree: the row "(no layer)" only shows when the project has layers and some types belong to none; a project without any layer shows its namespaces at the top.
- Language (issue "language of an object"): `explorer.outline` gives every type a `language` (id of the language pack of the declaring file; the answer leaves out the language of the namespace, which the web reader puts back, see `docs/server.md`) and `explorer.symbol` gives the same for the shown symbol. The tree shows a short name after every type row (`LANGUAGE_SHORT` in `web/src/features/explorer/consts.ts`, the tooltip has the full name from `languageName`), the details show the language name as a second label next to the kind. It is always shown, also in a project with one language. A nested type takes the language of the type that holds it.
- Details: breadcrumb, name with kind and visibility, documentation, ten metric tiles, member table with the chips All, Properties, Methods and "public only". The colour of a metric and of the complexity of a member comes from the thresholds in `config/default.toml` (`metrics.*`), which `explorer.outline` delivers; the number is always shown too, and the tooltip of a column or tile names the limits. The tiles of the coupling counts (`uses (Ce)`, `used by (Ca)`, instability) carry the note "upper bound" ("Obergrenze") while the newest scan did not check the language of the symbol with level 2 (ADR 0037): level 1 counts every reference, also the probable ones. The note comes from the `report` of `projects.list` and is absent until that list is read. A failure of the symbol keeps the tree.
- Source column (WP-45b): the right column shows file, position and code of the selected member, or of the selected type if no member is picked. `explorer.source` reads the lines of the declaration from the project folder as it is now (not from the scan), so a file edited since the scan can show shifted lines; the next scan fixes that. Only a project that is a folder on this machine has source; a Git project says so. A file that is gone gives the registered failure `SRC-201`, a file over 4 MiB `SRC-501`, a declaration over 400 lines is cut with a note. The path is resolved against the project folder and anything that lies outside it, also through a link, is refused. Line numbers and code are two plain `pre` blocks, so a long declaration costs two DOM nodes.
- Names in the code (issues #158, #171): `explorer.source` returns `spans`, the places where a symbol is named (one-line references of the scan). The code is still one `pre`, but each name is a small element with `data-symbol`; `Alt+click` on it opens the usages of that symbol (`showUsages`, the `title` says so). A plain click does nothing, and text that is not a reference stays plain. `Alt+Down` and `Alt+Up` select the next and previous member of the shown type in the order of the member table (nested types are skipped, the ends stop); with no member selected they start at the first or the last. A file edited since the scan can shift the places; the command leaves out those that do not fit their line.
- Syntax colours (ADR 0064): `explorer.source` also returns `tokens`, runs `{ line, start, end, class }` that the server cuts with the `highlights.scm` of the language pack. `segments()` merges them with the names; a coloured piece is a `span` with the class of its colour (`--syn-*` tokens of the three themes), a name inside a coloured run keeps `data-symbol` and the colour. A language without `highlights.scm` stays plain. The lines are parsed as the excerpt of the declaration, so a name that needs the surrounding file may be coloured as plain.
- Parse time per language (issue #237): the analyze stage times each file and sums the microseconds per language; a full scan stores them in `parse_times` (schema version 9), an incremental scan copies the rows of the previous snapshot, so the column shows the time of the last full scan (in CPU time over all workers, not wall clock). The figure is the whole analysis of a file (parsing, symbols, metrics, fingerprints), not the parsing alone; the first file of a language also pays for loading its pack. A snapshot from before version 9 shows a dash. A language that first appears in an incremental scan shows a dash until the next full scan; a language that has disappeared keeps its row, which is not shown because the table starts from the files. `projects.list` carries it as `parse_micros` per language.
- Deviations from the mock: the code has no hover preview of type names; "Layer graph" (`G`) opens the dependency map with the layer of the selection selected (the layer comes from `explorer.symbol`; the button and the key are off for a symbol that no layer owns); "Open in editor" (`E`, `Alt+Enter`) builds the link of the setting `editor` from the folder of the project and the file and first line of the symbol and hands it to the browser (only for a project that is a folder on this machine; unit tests of the link and the keys); the tab "Dependencies", the metric "Test names the type" and the base type in the header are missing (the data model has none of them); the access column shows the visibility only; the usage count opens the usages screen; the signature column shows a dash where the language pack stores none; kind and visibility are shown as the keywords of the language, not translated; the C# qualified name of a type carries a prefix (issue #137).

## Annotations and alerts: what the API gives the UI (ADR 0068)

The commands are in `docs/server.md` ("Annotations and alerts"). For the screens:

- **Marks in the tree and the member table:** one call of `annotations.summary` per project gives a row per annotated symbol (`target`, `critical`, `notes`, `tasks_done`, `tasks_total`, `without_target`). The UI joins a row to a tree node by symbol kind and qualified name: `explorer.outline` types and `explorer.symbol` members carry `qualified_name` (the outline may leave it out when it is the namespace, a dot and the name; the web reader puts it back before the tree uses it), the kind comes from the row itself. Overloads share a qualified name; a summary row has `target.parameters` to tell them apart.
- **Annotations of one symbol:** `annotations.list` with `symbol`.
- **Alerts:** `alerts.list`; the count in the top bar is the `open` field and the WebSocket event `alerts_changed` (`project`, `open`), after which the UI reads the list again. The event carries no text.
- **Shortcuts:** `K` (critical mark), `N` (note) and `T` (task) are the `shortcut` of `annotations.mark_critical`, `annotations.add_note` and `annotations.add_task` in `GET /api/v1/commands`; the registry only names them, the UI binds them.
- **Rights:** the UI is the browser client of `serve` (ADR 0072) and holds `annotate`. A caller without it gets `API-201` on a change and may still read.

### The screens of ADR 0068 (marks, notes, tasks, alerts)

- **Marking (variant B):** the member table shows the stripe and the label "Critical" and no shield; the tree shows the stripe, a small shield and, on a folded group, the number of critical symbols below; the details show the shield and the label; the dependency map draws a critical node with the stripe and the label "K" and has the switches "Highlight critical" and "only critical and their neighbours" (client side, no new layout). Critical is never shown by colour alone.
- **Side panel of the explorer:** the tabs Info, Critical (the shield, with an `aria-label`), Notes and Tasks, with arrow keys between them; an inactive tab drops its name and keeps its counter when the panel is narrow. For a type the Info tab holds the source pane; for a member the source stays in the middle column and the panel shows the facts of the member. The keys `K` (toggles the mark), `N` and `T` act on the selection and are also entries of the quick search.
- **Counters and loading:** `annotations.summary` is read once for each project and snapshot, and again after every change made in the browser; the texts under the rows (switch "Show annotations") are read once with `annotations.list` by kind. A server without the commands, or the static export, shows no tabs, column, switches or marks.
- **Text of notes:** a small Markdown subset (bold, italic, code, links with `http` or `https`); everything else, including HTML, is shown as text.
- **Alerts:** the bell in the top bar shows the `open` count of `alerts.list` and follows the event `alerts_changed`; the drawer has the tabs Open, Changed, Removed (orphaned targets are listed here) and Dismissed, dismisses one alert with the cross and all alerts of a tab after a question (`confirm: true`), jumps to the symbol on a click, and offers "Reassign" (to the `closest` symbol, `annotations.update` with `target`) and "Remove mark" for an orphaned target. Escape closes it and the focus goes back to the bell. The sentence under a name is built from the fields of the alert, because the server sends no text.
- **Board "Annotations" (`/annotations`):** one column for each status, the filters "Mine", "Only critical" and "Due". A task changes its column with the status list of its card (no drag and drop). The server has no command that names the caller, so "Mine" uses the author the server gave to the last annotation made in this browser and stays off until there is one.
- **Known limits:** overloads share one target because the member rows carry no parameter types (`parameters` is left out); the legend and the short view of the mock are not built.

## Quick search (screen 4, WP-46)

`Ctrl+K` (`Cmd+K` on a Mac) or the search field of the top bar opens the overlay (blueprint B.4, mock `Palette.dc.html`). It searches the newest scan of the active project with the command `search.query` (read right, no source text; see `docs/server.md`). Screenshots: `docs/screenshots/search-hell.png`, `search-petrol.png`, `search-dunkel.png`.

- Input with a magnifier, hit count and time (green) and the key `Esc`, chips All, `t:` Types, `m:` Members, `>` Commands, `f:` Files and `@` All projects (a prefix in the input wins: `t:` types, `m:` members, `>` commands, `f:` files, `@` all projects; the chip is reset to All each time the overlay opens), grouped hits with the match marked (the first place where the text occurs in the name), preview of the chosen hit with its actions, footer with the keys (arrows choose, `Tab` filter) and the fuzzy-search hint. The list is virtualised and holds at most 50 hits.
- Keys: Up and Down choose, `Enter` opens the hit in the explorer (the rows down to it open, because external navigation opens nodes), `Tab` and `Shift+Tab` change the chip, `Ctrl+C` (`Cmd+C` on a Mac) copies the qualified name when no text of the input is selected; `Ctrl+K` while the overlay is open keeps text and hits, `Esc` closes and gives the focus back to where it was.
- Commands (`>`): the screens (projects, explorer, settings) and "scan project again" for the active project.
- Files and all projects (issue #171, #178): `f:` (chip "Files") lists the files whose path matches (fuzzy, only files that declare a type), `search.query` returns them in `files` and the group "Files" follows the members in "All" too. A file shows its size in lines; `Enter` opens its first type in the explorer. `@` (chip "all projects") asks the command with `all_projects`: symbols and files of the newest scan of every project, the line names the project when it is not the open one, and `Enter` makes that project the open one before the explorer shows the hit. `@` shows no commands.
- Deviations from the mock: the preview shows kind, qualified name, file, the first lines of the documentation and three tiles (lines of code, members, maintainability) that it reads with `explorer.symbol` for the chosen hit (a hit that cannot be read shows none of them); "Show in graph" (`Ctrl+Enter`) opens the dependency map with the layer of the hit selected; `Alt+Enter` opens the declaration of the hit in the editor (the line comes from `explorer.symbol`); the key hints of the preview say `Ctrl` (the `Cmd` variants work on a Mac); the footer shows the number of symbols of the index after the first search of the project (an empty index shows 0); the time shown is the round trip of the command, not the time of the query alone; the hit of a member of a nested type opens the member within the nested type.

## Top bar (blueprint 15.2, issue #167)

Logo and product name, then, once a project is open, a slash, the project name (a link to the projects screen) and a chip, then the search field with a magnifier, which takes the room left of it up to 520 px as in the mocks. The chip shows the branch of a Git source or "Working folder" for a folder, and how old the newest scan is (`app-chip-folder`). Nothing is shown for the project while none is open. The HTML export uses the same bar with the project name and no chip. Deviation: the chip never says "Beobachtung aktiv": the server of the UI does not watch folders (see below).

## Status bar and language switch (WP-47)

The footer of every screen (blueprint 15.2, 15.5, mock `Main.dc.html`) shows only measured values: the connection state, the number of projects and types (summed from `projects.list`), the size of the reference index of the open project (the references of its newest scan, `projects.list`), the start time and the memory of the program (command `status.info`, read right, read again every 5 seconds), and on the right a switch `EN | DE`. The switch calls `setLanguage`, like the language field in the settings, so both stay in step and the choice is stored in the browser. Numbers are written in the chosen language (`1,220` / `1.220`).

- Start time: milliseconds from the start of the program (`run::execute`) until the server answers on its port. A server that is not started by `codeskimr serve` (the test server) reports none, and the bar leaves the item out. Memory is the physical memory of the process (crate `memory-stats`, Linux, macOS, Windows); if the system does not tell, the item is left out.
- Query time (issue #166): `runCommand` times the round trip of `search.query`, `explorer.symbol`, `usages.query` and `graph.layers` (`TIMED_COMMANDS` in `web/src/shared/api/consts.ts`; the key is the budget in `status.info`). The last value per budget is kept for the session (`web/src/shared/api/timings.ts`). The status bar shows the round trip of the last timed command as "Query 4 ms" (left out before the first one); the performance screen shows the values in the budget list, with a dash for a budget that was not measured yet. The round trip includes the network of the local server and the drawing of the answer is not part of it, so it is an upper bound of the server time. The full scan budget shows the duration of the last full scan of this session as it was; for a project under 100k lines it is shown without the good or bad colour, because the budget is defined for 100k lines.
- Deviations from the mock: "Watching for changes" and "Sample data" are not shown. The server of the UI does not watch folders (only `scan --watch` does) and there is no sample data, so showing them would be decoration. The texts `app-watching` and `app-sample-data` stay in `locales/` for the packages that add them.

Screenshots (1440 x 900): [Hell](screenshots/status-hell.png), [Petrol](screenshots/status-petrol.png), [Dunkel](screenshots/status-dunkel.png).

## Usages (screen 6, WP-53)

`U` in the explorer (or the "Usages" button, or a click on the usage count of a member) opens the usages of the selected member, or of the selected type if no member is picked. The screen (`/usages`, no button in the rail, like the mock) uses one command, `usages.query` (read right, no source text; see `docs/server.md`). Screenshots: `docs/screenshots/usages-hell.png`, `usages-petrol.png`, `usages-dunkel.png`.

- Toolbar: a button "Back to the symbol" (opens the symbol in the explorer; there is no level switch here), direction (both, who calls, what is called), depth (1, 2, 3, all; 1 at first, so list and diagram show direct usages only (by request of the product owner this deviates from mock 6, which shows depth 2); the hit list always shows direct usages only, a greater depth widens the diagram; "all" is cut to `mcp.max_depth`) and "Show tests". Every change reads the usages again.
- Graph: one column per step of callers to the left, the symbol in focus (yellow ring), one column per step of callees to the right. A card shows the type and member name, the kind badge, the layer and the number of places; a click on a card shows that symbol in the side panel, a double click, or Enter on a focused card, makes it the focus. The toolbar has no level switch; a back button leads to the symbol in the explorer, and the graph button of the rail stays marked. On the type level of the map a double click on a type makes it the focus (there is no "focus on this type" button). The cards of a column hang around the middle of their parent in the column nearer to the focus, not around the focus itself; the columns are 90 px apart so the lines do not run in a bundle between them. Lines are blue (calls, the accent colour), orange (the focus uses), violet (tests) and dashed grey (presumed). Per column at most 30 cards are drawn, the heading says how many more there are. A reference that closes a cycle is listed but not drawn backwards. The graph has a fixed height and scrolls inside its frame, so the hit list stays at the bottom of the screen however many callers there are (issue #169). A legend in a strip at the bottom of the frame, under the scrolling graph so that it covers no card (the mock draws it over the graph), explains the lines (calls, uses, presumed via interface) and says that the number on a card is the number of places. The column "Calls / reads" is shown with its heading whenever the walk of callees was asked for, also when nothing is called (it is left out only for the direction "who calls").
- Hit list: kind (call, read, write, test and so on), the calling symbol, file and line, and the certainty. A click on a row lights the path of that hit in the graph (the card of the symbol and the lines through it; the rest turns faint) until a card is picked or the symbol changes. F8 and Shift+F8 step through the hits, `Enter` (or a double click) shows the selected hit, or the symbol in focus if none is selected, in the explorer.
- Side panel: the symbol of the card that was clicked in the graph (the focus until one is clicked), signature, counts (places, files, layers), the impact of a change (symbols reached, layers, public interfaces), the note that constants, properties and interface members work the same, the accuracy and the button "Open in Explorer".
- **Approximation:** for the languages in `ui.approximate_languages` (default Python, C# and Kotlin, the languages below 99 % agreement with the compiler, `docs/accuracy.md`) the accuracy card of the side panel shows a chip "Approximation" and a short note that a usage can be missing. The list comes from `GET /api/v1/ui-config`; a server that does not send it marks nothing. Mock 6 shows the chip and the note.
- **Certainty (ADR 0033):** every hit says whether level 2 verified it. The pill of a hit reads `verified`, `unchecked` (found by name resolution only) or `presumed` (level 1 itself is unsure); the side panel counts them apart and, while no hit of the answer is verified (`level2: "unavailable"`; `"active"` as soon as one is), says that the usages and the impact are preliminary and may be incomplete or contain wrong hits. The sentence says that level 2 did not check these hits (not that no indexer exists: the screen does not know that), and that level 2 runs with `codeskimr scan` in a terminal and with a scan in the browser (if switched on and confirmed), never with a scan through MCP. While some hits are verified and others not, a shorter sentence says that part of the hits was not checked. Verified hits are sorted first. `verified` and `level2` come from the stored references: level 2 sets them when the owner confirmed it and an indexer checked the file (`docs/level2-import.md`).
- Deviations from the mock: the hit list shows file and line, not the code line (reading code needs `read_source` and the token, which this screen does not use; follow-up issue); "Alt + click on a symbol in the code" has no effect because the source column has no symbol spans yet (same reason as in the explorer); the hit list shows the callers (or, for "what is called", the callees), not both; the graph shows type uses of the symbol as cards too; "Open in editor" is not on this screen; the footer shows the connection, not "Reference index" or the query time.

## Scan and performance (screen 5, issues #153, #168, #210)

- Cancel: while a scan runs, the header shows the button "Cancel" with the key `Esc` (not while typing in a field). It calls `projects.cancel`; the screen changes when the event stream reports `scan_stopped` with `cancelled`, so a cancel that came too late changes nothing. The scan ends without a snapshot; the call that started it answers `PRJ-303` ("The scan was cancelled").
- Cores: the fourth figure shows the threads of the analyze stage while a scan runs and a dash otherwise: the cores the system offers (`status.info` `workers`), but never more than there are files to analyse, because the stage starts no more threads than that.
- Files left out (issue #635, ADR 0085): below the language table, a card lists the files the newest scan left out, each with path, error code (the message of a code as visible text once, under the first file with that code) and "missing in the result" or "shown as the previous scan saw it", and "and N more files" if the scan left out more than `scan.max_left_out_listed`. Nothing shows if none was left out. The mock `Scan.dc.html` has no such card; it is an addition for review.
- Language table (issue #210): language, tier, files, lines and symbols. The tier (`full` or `basic`) comes from the `language.toml` of the installed pack (`projects.list`, `languages[].tier`; read from the manifests only, so no grammar is compiled; a pack with an invalid manifest is left out, and a table that could not be read is tried again at the next call); a language without an installed pack shows a dash. The symbols are the symbols of the newest snapshot whose file is of that language (`languages[].symbols`).
- Header: next to the name of the project it shows `main @ e07c4a1` (branch and the first seven characters of the commit), or what of the two is known: a folder project has no branch, and a project without a commit shows nothing.
- Time per stage (issue #210): `scan_progressed` carries `elapsed_ms`, the milliseconds since the stage started, measured by the server. A stage reports once more when it is over, with the same counts and its whole time; the screen shows that time for a finished stage, and the time since its first report (as the browser saw it) while it still runs.
- Starting a scan (the Projects screen: "Add and scan", "Scan again", the key `R`, "Stage 1 only", "Full scan") opens this screen for the project; a scan that is started elsewhere (CLI, MCP, another tab, the file watcher) does not move the page. Adding a project has no id before the first report, so the first `scan_progressed` of a project that this tab did not know when it added shows the screen (a second new project that is scanned by another channel at the same moment can take it, which is accepted). Until the first report of the new scan comes, the header says "Scan starting" and the run before it is not shown as if it were this one.
- Share per stage: every stage row has a bar (`role="progressbar"`, named like the stage) and a percent figure. A stage has a share only once it has finished a unit of a known total (the parse stage counts files); a stage that works without one (resolve and metrics are single calls) has no `aria-valuenow`, shows a moving bar and a visible note ("progress cannot be measured"), linked with `aria-describedby`. The figure of the whole scan stays at 99 until the scan is done. Stage 2 (indexers) shows a line with the language, without a count.
- After a reload: the event bus keeps the last report of each stage of each running scan (`EventBus::running_scans`, forgotten at `snapshot_created`, `scan_stopped` or when the scan thread ends, a panic included). A new event stream starts with these reports, so the page shows the running scan with its counts and its real times (`elapsed_ms` moves the start back). A queued older report never moves a stage count back.
- Deviations from the mock: the pipeline stage is called "Save" and not "Symbols and members": symbols and members are made by the stage "Parse" together with the types, so the real pipeline has no stage of that name, and the screen shows the stages as `StageKind` knows them.

## Dependency map (screen 3, issue #163)

- Toolbar: level "Layers" (default) or "Namespaces" (`graph.layers` with `level`); the choice reloads the map. The third button "Type focus" (issue #198) shows one type in the middle with the types that use it above and the types it uses below (`level: types`, `focus`); it is enabled when the explorer has a type selected, and the side panel of another selected type offers "Show this type in the middle". More than 12 types per side are cut and noted. Resetting the map (project change) leaves the type level, because the focus is forgotten. Boxes, links and the selection are matched by the name of the box; if two drawn types have the same qualified name (for example in two files), the server adds the id (`Demo.Checkout #12`) so that they stay apart (issue #234). "Open in explorer" then opens the selected type itself. Behind the boxes every layer row has a stripe with the name of the layer (`bands` of the answer). On the namespace level a box shows the number of types of its namespace, and a second group "Depth" (all, 1 level, 2 levels; issue #198) merges the namespaces into their first segments (`App.Views.Board` and `App.Views.Menu` become `App.Views` at 2 levels): the types add up, references inside one merged box are not drawn and the others add up. The merge is done by `graph.layers` (`depth`) before the layout. A merged box sits in the row of a layer only if a layer owns the merged name itself (`App` at depth 1 belongs to none if the layers are `App.Domain` and `App.Views`); otherwise it is placed by its edges like any namespace of no layer. The merge works on the names as they are stored; since ADR 0036 C# names start at the namespace, so the merge gives the namespaces that a C# developer expects (projects scanned before need one new scan, which the program makes a full scan by itself). A change of the depth clears the selection, because the selected box may not exist any more.
- Deviations from the mock: the level "Types" is the button "Type focus" and shows one type with its neighbours, not all types at once; the key `G` in the explorer opens the map with the layer of the selection selected; the switch "violations only" is off on the namespace level because no violation is derived there yet (`violates_layering` is false for all links, issue #45); long namespace names are cut inside the fixed box width and show the full name as a tooltip; the map is drawn with HTML and SVG up to the layout limit of 200 nodes, canvas follows after 1.0 (ADR 0080, issue #625).

## Statistics (screen 20, ADR 0081)
