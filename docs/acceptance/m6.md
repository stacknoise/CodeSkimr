## Measurement of the Git source, export and secrets

Measured with `tools/acceptance/m6-measure.mjs`: it creates a throw-away Git repository below the temp folder (a bare remote and a working copy), runs the release binary with its own data folder, plants a canary string in a method body and in the environment of every command, and removes everything at the end. The raw output of the run is in `docs/acceptance/m6/measure-output.txt`.

### Git source (local `file://` remote)

| Step | Result | Wall time |
|---|---|---|
| clone and scan (first) | 1 file, 3 symbols | 1.1 s |
| scan again, nothing new | 1 file, 3 symbols | 1.1 s |
| update after a new commit on `main` | 2 files, 6 symbols, 2 references | 1.0 s |
| branch `dev` | 3 files, 8 symbols | 1.2 s |
| missing branch | exit 1, `SRC-202` | 1.1 s |

Note: the CLI accepts a `file://` address as a Git source (no scheme is refused), while `docs/benchmarks.md` says the product accepts no `file://` URLs; one of the two is wrong (#388).

Limits of this result: a local repository without a network, so no TLS, no login and no pack of real size; the times say only that nothing in the path is slow, not how a large private repository behaves. Each wall time is that of the whole command, among it the tool check of the scan (the .NET tools are missing in this container, which the command reports).

## Probe on the private repository (for the product owner)

`tools/acceptance/m6-private.ps1` runs on the product owner's machine only. It builds the release binary, then runs `scan` of the private Git address with the stored login (`--credential`), a second `scan` (update), `export` and a last `scan` without a login, all with `CODESKIMR_LOG=trace`. It then searches for the secret, which it reads from a hidden prompt, keeps in memory and never writes or prints:

- in the output of every command (trace level), in the export page and in every file of the data folder, as UTF-8 and as UTF-16;
- in the Git configuration of the cache for a user or password in an address;
- in all files outside the Git cache for the usual token patterns (`ghp_`, `github_pat_`, `gho_`, `glpat-`).

The result file `ergebnis-m6.txt` in `%USERPROFILE%\codeskimr-abnahme-m6` holds numbers and yes/no answers only: no names, paths or addresses, so it can be pasted into the project chat. Before the run the login has to be stored once (`codeskimr credential login` or `credential set`). The script has not been run: no PowerShell is available in the container, and the repository is private. Its search logic follows `m1-m2`'s `private-reference.ps1`; the product owner should look at the first lines of the result for errors of the script itself before reading the numbers.

## M5 measuring frame

M5 (WP-67) waits for level 2 and #145. `tools/acceptance/m5-measure.mjs` runs `tools/accuracy/measure.py` per language, prints one table with level 1 and level 2 in separate rows and judges level 2 against the threshold of ADR 0033 (decision 14): precision and recall of at least 99 % on at least 150 sampled symbols. Nothing is entered here: the numbers belong in `docs/acceptance/m5.md` once level 2 is done. A trial run in this container measured TypeScript only; Python (Jedi) and Rust (rust-analyzer) are not installed here, and the script says so instead of printing a number.
