## Budgets

Measured with `tools/acceptance/m4-measure.mjs`: it starts the end-to-end server of the app (release build), scans a folder (CodeSkimr itself: 594 files, 9,189 symbols, 94,949 references, first scan 1.7 s) and calls the REST commands with timing in the client, so every number includes the HTTP round trip on the loopback address. The project is larger than in the first run (521 files, 31,936 references), so the scan times are not comparable.

### Graph layout (`graph.layers`)

| Measurement | Result |
|---|---|
| Benchmark `graph_layout/nodes_200` (domain layout) | 0.46 ms (unchanged since the first run) |
| Command `graph.layers`, CodeSkimr (6 layers, 28 links), 50 calls | median 1.74 ms, p95 2.72 ms, max 4.06 ms |

Limits of this result: the layer level of the real project has only 6 boxes. The namespace level (with depth) is measured by the same command but not separately here; the case "up to 200 nodes" is covered by the benchmark. Drawing on the canvas in the browser is not measured; blueprint 16.1 budgets the layout.

### Usages query at depth 2 (`usages.query`)

| Incoming usages of the symbol | Symbols | Median (first call) | p95 | Max |
|---|---|---|---|---|
| 0 to 9 | 143 | 1.8 ms | 4.9 ms | 7.7 ms |
| 10 to 99 | 89 | 2.8 ms | 7.0 ms | 193 ms (single call) |
| 100 to 999 | 120 | 6.6 ms | 8.0 ms | 9.4 ms |
| 1,000 and more | 48 | 6.8 ms | 9.1 ms | 9.5 ms |

The 400 symbols come from ten searches (`new`, `error`, `path` and so on); each was queried once with `way = both`, `depth = 2`, tests included. The largest symbols have 7,963, 1,954 and 1,344 incoming usages. The five symbols with the most usages were then queried 50 times each: median 7.2 ms over all 250 calls, p95 8.6 ms, max 11.1 ms. Largest symbol: `both` at depth 1: 7.3 ms, `incoming` at depth 1: 8.0 ms, `incoming` at depth 2: 8.9 ms, `outgoing` at depth 2: 3.5 ms. The one outlier of 193 ms (bucket 10 to 99) is a single first call and was not reproduced; it is not part of the budget statement (the budget is the median and p95 of repeated calls) but is noted here. Issue #165 is solved: the lookup of names, kinds, layers and paths no longer dominates.

## Comparison with the mocks

The mock sources in `docs/mocks/` are written for a design canvas whose runtime is not in the repository, and the published canvas is private. `tools/acceptance/render-mock.mjs` fills the small template language of a mock (`{{name}}`, `<sc-for>`) from the mock's own data function and renders it with Chromium at 1440 × 900. `tools/acceptance/m4-screens.mjs` takes the screenshots of the real UI over the end-to-end server in the theme Hell and the language German, as the mocks are drawn (blueprint 15.1). The mocks hold sample data, so only structure, proportions, labels and behaviour are compared, not the content. The comparison is by eye plus the inline values of the mocks; a pixel diff would be meaningless with different data. The `mock-*.png` files are from the first run (the mocks did not change); the `real-*.png` files are new.

Images are in `docs/acceptance/m4/`: `mock-*.png` is the mock, `real-*.png` the application.
