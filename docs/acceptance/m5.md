# Acceptance report M5 (WP-67), draft

Draft of 2026-11-15, commit `03bc2a6`. It collects the measured state of milestone M5 (blueprint 19: full tier for TypeScript/JavaScript, Python, Java, Kotlin and Rust, basic tier for every Tree-sitter grammar including Go, level 2 from SCIP indexes under ADR 0033). **The accuracy figures are not measured again here**; they are the figures of the level 2 run through the real path (`level2.md`, 2026-11-15, `main` at 6a5ffe1 plus #396), the hand-made figures of `docs/accuracy.md` and blueprint 17.2. The screen and scan side of the milestone is in `qa-m5.md`. Whoever repeats a measurement replaces the figure and the commit in the line.

Criterion of the milestone: corpus accuracy targets met per language; with level 2 confirmed, the accuracy of the languages that have an indexer is measured and shown separately. Threshold of ADR 0033, decision 14: on at least 150 sampled symbols, recall of at least 99 % and at least 99 % correct among the verified references, judged against a reference tool that is independent of the index.

Legend: ✅ met · ◐ met on the sample with a remark · ❌ not met (cause linked) · ⬜ not measurable

**Overall: M5 is not accepted as it stands.** Python and C# are below the threshold and Kotlin cannot be measured; open point 1 was decided on 2026-11-20 (these languages are shown as approximations), but the figures themselves are unchanged. The ✅ and ◐ rows below say what exists, not that the milestone is done.

**Reading.**

- **Rust, TypeScript, Java:** the threshold is met on both samples. The reference tool is the same engine as the indexer for all three, so an error of the engine itself would not show (`docs/accuracy.md`).
- **Python:** recall is 99 %, precision cannot be shown. Jedi is silent for 28 (seed 2: 67) symbols, all instance attributes, on which we have 163 (371) uses; where Jedi answers, precision is 90.1 % (87.6 %). The rest are import lines and annotations counted as uses (#250). The figure is a lower bound, not a proof of an error. An independent second reference (Pyright is the indexer itself) is missing.
- **C#:** the indexer attributes calls of overloaded extension methods to the first overload (#258, upstream draft in `docs/accuracy.md`); constructor calls (`new X(...)`) are missing in the index (#259); two cases are not traced (#395). Reports to scip-dotnet and scip-java: drafts exist (`docs/accuracy.md`); whether they are filed is not recorded here.
- **Kotlin:** the pack, the corpus (KotlinPoet) and scip-java exist, but there is no independent reference tool for Kotlin (no `kotlinc` in the container, no compiler API script). Nothing is estimated; it is not measurable with the current tooling.
- The private C# sample of 20 symbols (complete, without wrong usages, criterion of blueprint 17.2) is run by the product owner locally and is **not** in these figures.

## Level 1 (for comparison, never mixed with level 2)

Level 1 keeps every match and marks it unchecked (ADR 0033, decisions 6, 7). What counts is recall not lower than before PR #133 and the share of unchecked results per language. Hand-made samples of 150 symbols (blueprint 17.2, 2026-11-14): TypeScript 27.7 % precision and 62.7 % recall, Python 32.3 % and 81.1 %, Rust 59.2 % and 59.3 %, Java 46.7 % and 84.0 %, C# 28.8 % and 98.0 %. The precision is low by design (unchecked results are shown as such). **Open:** the share of unchecked results per language, which blueprint 17.2 asks to report, is not printed by the scan and is not reported here (without a level 2 index every level 1 reference is unchecked). What the scan does report is the share of `probable` references (name matches several symbols, `RES-301`): on CodeSkimr itself 148,936 of 166,439 (89 %, `qa-m5.md`). That is a different measure. The criterion "recall not lower than before PR #133" has **no verdict** here: the figures before #133 are not in the repository (⬜ not verified).

## Open points

1. **Decided by the product owner on 2026-11-20 (decision card): languages below 99 % are shown as approximations.** Python, C# and Kotlin (not measurable) are named as approximations in the release notes (`docs/release/notes-de.md`, `notes-en.md`) and in the UI. The figures are not changed by this decision; the UI sign is delivered by the work package of the budget thread, see `status-1-0.md`.
2. Python: an independent second reference for the precision (see above). Without it the precision of Python can neither be confirmed nor refuted.
3. C#: #258, #259, #395, and the private sample of the product owner.
4. Rust: 659 of 8,805 uses (7.5 %, measured with a hand-made index, `docs/accuracy.md`) have no level 1 symbol after ADR 0055; the target "under 1 %" is not reached (#436).
5. TypeScript #394 (curried function on the next line) and the import lines counted as uses (#250, Python 7.2 %, TypeScript 5.4 % of the references).
6. Not covered: Windows and macOS (#104, #131, #327). `level2.md` measured one machine, one cold run per language, no memory peaks of the indexers.
