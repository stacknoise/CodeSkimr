# 0071 – A level 2 switch in the projects screen: the server opens the console for the confirmation, revoking is one click

Status: accepted (Anton, 2026-11-18 09:55:53 UTC, decision card cmsg_01BurfeyeHWcU615RsoB5poQQLEwLHUSb7bqsFhpJxbaDX "Annehmen"; the decision itself was made on card cmsg_01BurfeyeHWcU615RsoB5poQT5ZHvQCebXqH6V5UNVNht4, option "switch opens console")

## Context

Level 2 (ADR 0033) runs the build tools of a project, so it has a consent that only the local owner can give: `codeskimr level2 confirm <project>` on a terminal, where the owner types the name of the project (addendum of ADR 0033, `SEC-403` for everyone else). Today the owner has to know the command, find the project id and use a terminal next to the browser. In the first test of the stage 2 scan this was the hurdle (blueprint 10.2 and `docs/manual/de/indexer.md` describe the two steps).

Rules that stand in the way, and how this ADR relates to them:

- **ADR 0028 (decision 2) and ADR 0030:** "The server never starts a process" for the editor link, and a command-line launcher "needs its own ADR and a security review". This is that ADR, for a different purpose and a much narrower launch.
- **ADR 0033 (decision 10 and addendum):** MCP, REST, CI and watch mode never stand in for the confirmation; the browser must not start build tools. This ADR keeps both: the browser never gives the consent and never starts an indexer.
- **ADR 0024 and S-04:** every route is guarded (Host, Origin, token, permission), routes without logic of their own, CORS closed.
- **Blueprint 3 (no literals, 40 lines, no `unsafe`):** values live in `consts` and `config/default.toml`.

The wish of the owner: switch level 2 on and off per project in the projects screen, see its state, and keep the terminal confirmation as the one and only approval.

## Options considered

- **A. Nothing changes:** the owner uses the terminal. Safe, but the screen shows a state it cannot change.
- **B. The browser gives the consent** (a dialog with the name typed in the page). Rejected: a script in the page, a browser extension or a stolen token would then give consent to run project code. SEC-403 and decision 10 of ADR 0033 exist to prevent exactly this.
- **C. The server opens a console window that runs `codeskimr level2 confirm` (chosen).** The approval stays the typed name on a terminal of the owner's own account; the browser only asks for the window.
- **D. Only show the command to copy.** Works everywhere, no new process. It stays as the fallback (decision 6), but as the only way it keeps the hurdle on Windows and macOS.

## Decision

### What the switch does

1. **Switching on opens the confirmation in a console window; the browser never approves.** A click on "Switch on" asks the server to start `codeskimr level2 confirm <project id>` in a new console window of the owner. The command is the existing one, unchanged in what it shows and asks (the warning about file and network access and the missing sandbox, name, location and branch, the typed project name, the re-read of the project afterwards). Whatever the window does, the page learns the result only by asking for the state again (decision 3). Nothing the page sends can carry a consent.
2. **Switching off is one click and needs no terminal.** The command `level2.revoke` takes the confirmation back for the project, as `codeskimr level2 revoke` does (`level2::revoke`). Revoking only removes a right, so it needs no terminal and no typed name. It does not stop an indexer that is running at that moment; the next start finds no consent (SEC-301), and the running one ends within its limits (ADR 0033, decision 11).
3. **The screen shows the state per project**, from the command `level2.status` (right `read`, no token needed like other read-only commands; it returns no path and no text of the project, and no path of the configuration file, because a path usually holds the user name and the command needs no token):

   | `state` | Meaning | Offered |
   | --- | --- | --- |
   | `on` | `[level2] enabled = true` in the user configuration and the project is confirmed for its current source, location and branch | "Switch off" |
   | `off` | the switch in the user configuration is on, the project is not confirmed (or the source changed since) | "Switch on" |
   | `not_enabled` | `[level2] enabled` is missing or false in the user configuration; the field `confirmed` says whether a confirmation exists anyway | the hint of decision 8, and "Switch off" if `confirmed` is true |
   | `locked` | team server (decision 9) | nothing, with the reason |

   The switch `enabled` is read from the **user configuration only** (`[level2] enabled`). ADR 0033, decision 9, also names "the user's own project record"; that way does not exist in the code (the project record holds the consent, not the switch), so `not_enabled` is correct whenever the user configuration lacks the switch. The words of ADR 0033 are not changed (accepted); this is the clarification.

   The answer also carries `launch`: `window` if this system can open the window (decision 5) or `copy` if the screen has to show the command. While a window is open, the screen asks `level2.status` again every `ui.level2_poll_seconds` (default 2) for at most `ui.level2_poll_max_seconds` (default 300); both values reach the screen through `GET /api/v1/ui-config` (ADR 0030, decision 3: public, no secret), not through `level2.status` and shows "waiting for the confirmation in the console window". The tool check of ADR 0033 (decision 8) is separate and unchanged: "on" says nothing about whether an indexer is installed.

### Routes and permissions

4. **Three entry points, each with one job.**
   - `level2.status` and `level2.revoke` are **registry commands** (blueprint 10.1) and are exposed over REST with `CommandApi::expose` only. They are **not** MCP tools: the tool list of blueprint 10.4 stays as it is, and a test pins that neither id appears there, because the MCP principal is the same `remote_client` as the one of the server.
   - `level2.revoke` is `read_only = false` (the registry flag), so it needs the installation token, and it needs the new permission **`RevokeIndexer`**. `remote_client` gets it; `ConfirmIndexer` and `RunIndexer` stay withheld from it. `level2::revoke` accepts `ConfirmIndexer` or `RevokeIndexer`; `level2::confirm` accepts `ConfirmIndexer` only. The origin test of ADR 0033 (`consent_origin.rs`) keeps its rule for `confirm`, `ConsentGrant` and `store_consent`, and is extended by exactly one allowed caller: the command `level2.revoke`.
   - **`POST /api/v1/level2/confirm-window`** is a **route outside the registry**, like the exchange and launch code routes (ADR 0028, decision 4; ADR 0030, decision 10), because it is the one thing in the product that starts a process. It has no logic of its own: it runs the guard and calls the application function `level2::open_confirmation` (decision 7). It takes `{ "project_id": <number> }` and answers `{ "launch": "window" }` or `{ "launch": "copy", "command": "codeskimr level2 confirm <id>" }`. The order of checks: Host and Origin, then `Sec-Fetch-Site` if the browser sent it (anything but `same-origin` and `none` gives `API-402`), the JSON content type (`API-101`), the token (`API-401`), that the peer address is a loopback address (`SEC-403` otherwise), the permission **`OpenConfirmation`** (new; held by `remote_client`, never by an MCP tool, because the route is not a tool) (`AUTH-401`), the body (`API-101`), the project (`PRJ-201`; `SEC-403` for unsafe text), the switch of the configuration (`CFG-105`, decision 8), the rate limit (`API-504`, decision 4a), then the launch. The rate limit comes last on purpose: a refused request (wrong right, unknown project, switch off) starts nothing and so needs no pause, and a click that cannot succeed gets its real reason instead of `API-504`.
   - 4a. **Rate limit and no repeated clicks.** In memory, per server: after a window was opened there is a pause of `level2.confirm_window_cooldown_seconds` (default 30) for **all** projects, and where the program can see that the window is still open (Windows), no second one is opened for the project until it ends. The pause starts when the program tries to start a window, **also when the start fails** (`APP-604`), so a holder of the token cannot start `osascript` as often as it likes. Requests refused before the launch (`PRJ-201`, `CFG-105`, `SEC-403`, guard errors) do not start a pause. A request inside the pause is refused with the new code `API-504`, HTTP 429 and a `Retry-After` header with the seconds left; it starts nothing. The pause is the same whether the first request came from this tab or any other client.
5. **Which process, exactly.** The program is the running one (`std::env::current_exe()`, an absolute path; never a lookup in `PATH`). The arguments are a list, never a string for a shell. The one fixed argument list is `level2 confirm --from-ui <id>`, where `<id>` is the numeric project id that the server writes itself from the project record (never the name, never the text of the request), followed by the global options the server was started with as separate arguments (`--data-dir`, `--config` and the overrides). The environment is the one of the server without `CODESKIMR_TRAY_CHILD` (ADR 0067, consequences). The standard streams belong to the new console. The program the server starts per system:

   | System | What starts | Why this is safe |
   | --- | --- | --- |
   | Windows | the program itself with the creation flag `CREATE_NEW_CONSOLE`, arguments as a list | no `cmd.exe`, no shell, nothing to quote |
   | macOS | `/usr/bin/osascript` with a **constant** script text `on run argv … tell application "Terminal" to do script (the quoted form of every item of argv, joined by spaces)`; the program path, `level2`, `confirm`, `--from-ui`, the id and **every** forwarded global option (`--data-dir`, `--config`, each override) are **separate `argv` items** | no value is ever part of the script text; `quoted form of` is applied to each item alone; the id is checked to be digits. A test (macOS CI job or a unit test of the argument builder) covers a path with spaces, a double and a single quote, `$` and a backtick |
   | Linux | **nothing** (decision 6) | |

   The list of terminal programs is **fixed in the code** (`Terminal.app` for macOS, the console of Windows) and not configurable: no key and no request can name another program. A project file cannot influence any of it (`level2.*` stays ignored there, S-04). The new option `--from-ui` of `level2 confirm` does two things only: it prints one extra line ("This window was opened by the CodeSkimr page in your browser. If you did not click it, close it.") and it waits for Enter at the end so that the answer can be read. It changes nothing about the consent.
6. **Linux and every unclear case: the screen shows the command to copy.** The server opens no terminal on Linux (no common terminal program, ADR 0067 made the same finding for the tray), and it also answers `copy` if the program is not run in an interactive desktop session (service, SSH session, container), recognised per system and never by guessing: Linux by a missing `DISPLAY` and `WAYLAND_DISPLAY`, or by `SSH_CONNECTION`; Windows by a process that does not run in the interactive window station (a service or session 0) or by `SSH_CONNECTION`; macOS by `SSH_CONNECTION` or by a missing login window session of the user. When the check cannot decide, the answer is `copy`, and if the launch fails (`APP-604`, the screen then shows the command as well). The command is `codeskimr level2 confirm <id>` with the id, not the name (a name can hold text that does not belong in a command line). A later ADR can add a positive list of Linux terminals.

### Where the code lives

7. **A port, an adapter in the composition root.** `codeskimr_application` gets the port `ConfirmationWindow` (one method, "open the confirmation for this project id", answers `Opened`, `AlreadyOpen`, `Unavailable`) and the function `level2::open_confirmation`, which holds the rate limit and the checks. The only adapter lives in `codeskimr` (`crates/app`), next to the browser start and the tray, which already start processes there. `codeskimr_server` stays free of `std::process`; a test greps for it. The adapter is `security-sensitive`, the package gets a security review. Blueprint 4.2 (dependency direction) is unchanged.

### When the switch is not in the configuration, and what revoking leaves

8. **The program never writes the switch.** Without `[level2] enabled = true` in the user configuration the screen shows `not_enabled`, the two lines of the manual to put into the file, and the words "in your `config.toml` in the data folder". The answer and the screen carry **no path** (it holds the user name, and `level2.status` needs no token). A command that prints the path does not exist today; if one is added later, the screen may name it. The route `confirm-window` answers the new code **`CFG-105`** (`level2_switch_off`), opens nothing, and the button is not offered. No command writes the user configuration (ADR 0065 writes the project file only), because the switch is the master key of level 2 and the browser must not be able to turn it.
9. **Team server: locked.** `level2.status` answers `locked`, `confirm-window` and `level2.revoke` answer `SEC-403`. A team server does not run indexers (ADR 0033, decision 10) until another ADR says so. The same refusal applies to a request whose peer is not a loopback address.
10. **Revoking keeps stored results until the next scan.** The references that level 2 produced under an earlier consent stay (`verified`) until the next scan re-resolves their files; nothing is deleted by the click, because the consent is about starting build tools, not about data that exists already. The screen says so after the click ("Checked results stay until the next scan; the next scan runs stage 1 only") and offers the normal rescan. No new run starts without a consent (ADR 0033, decision 9, and SEC-301).

### Errors

11. **HTTP status** follows the class of the code (ADR 0024, decision 9): `API-504` 429 with `Retry-After`, `CFG-105` 409 (the state of the configuration, not the request, is the reason), `APP-604` 500, `SEC-403` and `API-402` 403, `PRJ-201` 404, `API-401` 401, `API-101` 400.
12. **New codes** (all registered in `errors/error-codes.toml` and in blueprint appendix A, texts in `locales/de/errors.ftl` and `locales/en/errors.ftl`; the numbers were checked to be free on main and in the open pull requests on 2026-11-18, and are in no published release):
    - `CFG-105` `level2_switch_off`: level 2 is not enabled in the user configuration; the program does not enable it itself.
    - `APP-604` `confirm_window_failed`: the console window for the confirmation could not be started; the screen shows the command instead.
    - `API-504` `confirm_window_rate_limited`: a confirmation window was opened a moment ago; try again after the pause (retryable).

    `SEC-403` is reused for a caller or a place that may not confirm (team server, peer not on loopback, a project name that holds control or invisible characters, as for the command), `PRJ-201` for an unknown project, `API-401`, `API-402` and `API-101` for the guard.

## Consequences

- Blueprint changes (made by the implementing pull requests, label `blueprint-change`): 5.2 (permissions `RevokeIndexer` and `OpenConfirmation`), 9.3 (the consent paragraph: the window and the revoke), 10.2 and 10.3 (the route, the two commands, not in MCP), 14 (keys `level2.confirm_window_cooldown_seconds`, `ui.level2_poll_seconds`, `ui.level2_poll_max_seconds`, user configuration only), S-04 (one more route outside the registry and the one place that starts a process), 15.4 and every place that says that the server starts no process (the `E` row: "the server never starts a process for this" stays true for the editor link, with a reference to the one exception of this ADR), 14 (the `ui-config` answer carries the two poll values), appendix A (three codes). `docs/manual/de/indexer.md`, the English manual, `docs/server.md` (threat note) and `locales/` (screen texts in de and en, the extra line of `--from-ui`) follow.
- New work packages: (1) application: port, `open_confirmation`, status, revoke, permissions, codes; (2) app: the adapter for Windows and macOS, `--from-ui`; (3) server: the route and its guard order, with tests per step; (4) web: the switch, the state, the copy fallback and the polling; (5) manual and threat note. Packages 1 to 3 carry `security-sensitive`; Anton merges them.
- No new dependency. No `unsafe`: `std::process::Command` and, on Windows, `CommandExt::creation_flags` are safe functions.
- **What a hostile web page can do:** nothing. It has no token, CORS is closed, Host and `Origin` and `Sec-Fetch-Site` are checked, a form cannot send the JSON content type, and DNS rebinding fails at the Host check.
- **What a program with the token can do** (a script injected into the page, in spite of the CSP of ADR 0030; or a local program of the same user, which can read the keystore anyway, ADR 0024): open a window at most once per pause, and nothing more. It cannot confirm. It can revoke, which only lowers a right. A spoofed or unexpected window is the remaining risk: the owner would have to type the exact project name after reading the warning, and the extra line of `--from-ui` and the screen ("a window was opened at 14:02") let the owner notice a window that nobody asked for. This is the same residual risk as the pseudo-terminal in the addendum of ADR 0033 and is accepted.
- A confirmation is as strong as before: the same text, the same typed name, the same binding to source, location and branch. The browser gains no new way to run project code.
- Linux users see the command and copy it until a later ADR adds terminals. macOS may ask once for the permission that lets the program control Terminal; if the user says no, the launch fails with `APP-604` and the screen shows the command.
- On macOS the program cannot see whether the window is still open, so there only the pause protects against repeated clicks.
- Not decided here: writing the switch into the user configuration from a terminal command (`codeskimr level2 enable`), a Linux terminal list, a confirmation in the team server, and a sandbox (ADR 0057).
