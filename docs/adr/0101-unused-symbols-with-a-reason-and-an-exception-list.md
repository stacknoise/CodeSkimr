# 0101 – Unused symbols come with a reason and an exception list

Status: accepted (the scope was decided by the product owner on 2026-11-23, "ungenutzte Symbole mit Begründung (E3)" in version 1.1; the mock `erw-ungenutzt` was approved on 2026-11-26). The steps below are built one pull request each; this record is written with the first. Steps 1 to 4 are built, and the judgement was made fast for very large projects (#763).

## Context

The tab "No usage found" of the statistics screen (ADR 0081) lists the symbols nobody uses with an assessment: very likely unused, public, uncertain. A user cannot see why a row got its assessment, cannot say "this one stays on purpose" so that the number goes down for good, and neither a script nor an agent can ask the question (no CLI command, no MCP tool). The concept (`entscheidungen/erweiterungen-nach-1-0.md`, E3, K2, K3) asks for a reason per row, an exception list in the repository, and the doors `codeskimr unused` and `find_unused`.

## Decision

1. **Reason per row (step 1).** Every row of the ranking `unused` carries `reason`, one of `private`, `internal`, `public`, `approximate`. It follows from the visibility and from whether the language is an approximation (`UnusedReason::of`, in step with `Assessment::of`), so it never says more than the assessment knows. The UI shows it in the column "Reason" instead of the column "Visibility" (the reason names the visibility). Reasons the scan cannot know yet (entry point of a framework by attribute, interface member with implementations) are not invented; they can be added as further values when the scan stores what they need.
2. **Exception list (step 2).** `.codeskimr.toml` of the project may hold `[[unused.ignore]]` tables with `paths` (globs on the relative file path), `symbols` (globs on the qualified name) and a mandatory `reason` text; at least one of `paths` and `symbols` is needed (an entry with both needs a match in each; `*` is any run of characters, `?` one character), an entry without a reason is refused (`CFG-101`). The list stands in the repository, so the whole team sees the same. A symbol that matches an entry is no longer counted in "No usage found"; the tab lists such rows below the table in a group "Left out" with the reason of the entry. The list is read from the project file only; an entry in the user file or on the command line is accepted by the configuration but has no effect on the statistics, because a team list belongs to the repository. A project file that cannot be read or holds an invalid entry makes the statistics fail with the code of the scan (`CFG-102`, `CFG-101`), so no symbol comes back unnoticed. The tables are trusted in a project file (unlike `level2`, `editor`, `ui` and `export`): they can only hide rows from a list, never run or open anything.
3. **Doors (step 3).** `codeskimr unused [--json]` and the MCP tool `find_unused` answer the same as the tab: rows with assessment and reason, the left-out rows separately, `schema` version, `stale` when the files are newer than the scan. This is the first of the commands of K3; the MCP list grows by one tool, from 14 to 15, as the concept plans (the limit of 17 of ADR 0097 stays in sight; `impact_of_diff` is the next). Both read one function, `codeskimr_application::unused::UnusedSymbols`, which the tab uses as well (the judging of the facts against the exception list), so the three doors cannot drift apart. The tool and the command take `kind` (`all`, `types`, `functions`), `language`, `assessment`, `include_tests` and `limit`; the counts in the answer are those before the limit and before the `assessment` cut. A list over the limit is cut with the notice `MCP-501`.
4. **"Keep on purpose" (step 4).** The button writes an entry into the project file of a folder project (the same way as the layer editor, ADR 0065); for a Git project there is no file and the button is off. "Lift" removes the entry again. The commands are `unused.keep` (project, qualified name, reason) and `unused.lift` (the entry as the statistics show it, so a list that changed in the meantime is refused with `CFG-101` instead of lifting another entry). The screen adds the date of the day to the reason text; the author is not written, because the file lives in the repository and its history names who changed it. A name with `*` or `?` is refused (`CFG-101`), because as a pattern it would cover more than the symbol. Both commands need the right to manage and write the project file like the layer editor does (a link or an oversize file is refused, the file is replaced as a whole).
5. **Name.** The tab stays "No usage found"; "dead code" would promise more than CodeSkimr knows.
6. **Not decided here.** "No new unused symbols" as a rule of `codeskimr check` for CI (open question 5 of the concept).

## Consequences

- The number in the tab and on the overview card counts without the left-out symbols once step 2 is in; until then it is unchanged.
- With exception entries the answer is judged from the stored numbers of the symbols without usages only (`CodeStatistics::unused_facts`, read through the partial index `statistics_by_place`), not from the facts of every symbol (ADR 0091): the symbols with usages are never loaded, the test marks are those stored with the numbers, and the glob matcher allocates nothing. The first version loaded and judged every symbol and took about 8 to 9 s and 1.4 GB per request at 2,000,000 symbols, judging alone (#763). Measured on a release build with the synthetic graph of the statistics benchmark (`STATISTICS_BENCH_SCALE=100`, 2,000,000 symbols, 447,000 of them unused): reading the unused symbols takes about 1.5 s (reading every symbol took 15.7 s), judging 500,000 symbols against 5 entries takes about 0.17 s. The cost is linear in the number of unused symbols, so a project with fewer unused symbols is faster. The result is not kept per snapshot and rule set; that stays open if a real project needs it.
- Texts of the reasons exist in German and English in `locales/`.
